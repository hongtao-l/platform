## 一、业务背景

### 业务场景
面向海外宠物主人的智能喂食器管理 APP。用户通过 APP 绑定智能喂食器设备，实现远程手动投喂、定时投喂计划、投喂速度调节等功能。支持设备状态监控（在线/离线、余粮状态），并接收推送通知。后续版本将集成摄像机设备。

### 用户痛点
- 出门在外无法给宠物喂食
- 定时投喂计划不够灵活
- 无法掌握投喂速度和余粮剩余情况
- 设备离线时不知道、余粮不足时无提醒

### 产品目标
- v1.0.0：基础设备管理 + 投喂控制 + 账号系统 + 消息通知
- 核心闭环：登录 → 绑定设备 → 手动/定时投喂 → 接收通知

## 二、名词解释

| 术语 | 说明 |
|------|------|
| 喂食器 | 智能宠物喂食器硬件设备，通过 Wi-Fi 连接云端 |
| 手动投喂 | 用户在 APP 上即时触发一次性投喂动作 |
| 定时投喂 | 用户预设投喂时间点，设备按时自动执行投喂 |
| 投喂速度 | 出粮速率（快速/中速/慢速），影响每秒钟出粮量 |
| 余粮 | 设备内置粮仓中剩余的食物量，支持低量告警 |
| 设备在线 | 设备与云端保持 MQTT/WebSocket 长连接 |
| 设备离线 | 设备断网或断电，无法接收投喂指令 |
| 设备绑定 | 用户通过输入设备 SN 码或扫码将设备关联到账号 |
| 主账号 | 设备首次绑定的用户，拥有设备完整控制权限 |
| 邮箱登录 | 使用邮箱 + 密码方式注册和登录 |
| 喂食历史 | 每次投喂的时间、数量、触发方式（手动/定时）的记录 |
| 喂食弹窗 | 在设备管理首页弹出的快速投喂操作面板 |

## 四、场景穷举分析

#### 4.1.1 功能概述

| 条件项 | 最小值 | 最大值 | 默认值 | 超限行为 |
|--------|--------|--------|--------|----------|

| 单次投喂份数 | 1 | 10 | 1 | 超限禁用"+" |
| 投喂速度档位 | 慢 | 快 | 中 | 三档固定 |
| 定时时间精度 | - | - | 分钟级 | 不设秒级 |

#### 4.3.5 状态流转

投喂计划状态：
- **生效中** → 用户手动关闭 → **暂停**
- **暂停** → 用户手动开启 → **生效中**
- **生效中/暂停** → 用户删除 → **已删除**

设备状态：
- **在线** ←网络恢复→ **离线**
- 离线状态下所有投喂操作不可用

## 五、跨模块联动分析

### 5.1 状态变更的连锁影响

| 触发事件 | 影响模块 | 联动行为 |
|----------|----------|----------|
| 设备绑定成功 | 设备管理首页 | 刷新设备列表 |
| 设备解绑 | 设备管理首页、喂食器控制面板、消息 | 移除设备卡片、关闭控制面板、清理设备消息 |
| 设备离线 | 设备管理首页、喂食器控制面板、消息 | 显示离线状态、禁用投喂操作、推送离线告警 |
| 设备上线 | 设备管理首页、喂食器控制面板 | 恢复在线状态、恢复投喂可用 |
| 余粮不足 | 设备管理首页、消息 | 设备卡片显示低量提醒、推送通知 |
| 退出登录 | 全部模块 | 清除本地数据、回到登录页 |
| 定时投喂执行 | 消息 | 可选推送"投喂完成"通知 |

### 5.2 需要通知/刷新的场景

| 场景 | 通知方式 | 刷新触发 |
|------|----------|----------|
| 新增定时计划 | - | 定时计划列表刷新 |
| 删除定时计划 | - | 定时计划列表刷新 |
| 投喂完成 | 可选推送 | 喂食历史刷新（如有） |
| 余粮不足 | 必须推送 | 设备卡片余粮状态刷新 |
| 设备离线 >5分钟 | 必须推送 | 设备卡片状态刷新 |
