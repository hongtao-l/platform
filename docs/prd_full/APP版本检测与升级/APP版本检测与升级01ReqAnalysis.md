## 一、业务背景

### 业务场景
CareCam Pro 作为 IPC 摄像机配套 App，通过 APK 侧载方式分发给用户。用户无法通过应用商店获取版本更新通知，缺乏升级感知渠道。当 App 修复关键 Bug 或新增功能时，需要让用户及时知晓并完成升级。

### 用户痛点
- 用户不知道有新版本可用，持续使用旧版本（含已知 Bug）
- 缺少版本号展示入口，用户无法确认当前安装版本
- 无主动检查更新的能力

### 产品目标
- 提供自动检测 + 手动检测双通道，确保用户能获取版本更新信息
- 非强制升级，尊重用户选择权，避免打断用户操作
- 每次启动均弹窗提示，点击「立即更新」后标记已升级，同会话内不再弹（便于演示验证）

## 二、名词解释

| 术语 | 说明 |
|------|------|
| 版本号 | 语义化版本格式 `major.minor.patch`（如 `1.2.0`），数值越大版本越新 |
| 强制升级 | 弹窗不可关闭，用户必须升级后才能继续使用 App（本需求不做） |
| 非强制升级 | 用户可选择「立即更新」或「稍后提醒」，关闭后可继续使用 |
| 自动检测 | App 启动时静默请求版本接口，有新版时弹窗提示 |
| 手动检测 | 用户在关于页面主动点击「版本更新」触发检测 |
| 会话已升级标记 | `hasUpgraded` 内存标记，点击「立即更新」后置为 true，同会话内再次检测直接返回「当前已是最新版本」 |

### 3.1 功能列表总览

## 四、场景穷举分析

### 4.1 启动自动检测

#### 4.1.1 功能概述
- App 启动时自动请求后端版本检测接口
- 对比当前版本与最新版本，有新版本时弹出升级弹窗
- 每次启动均弹窗（便于演示验证），点击「立即更新」后标记已升级，同会话不再弹

#### 4.1.2 正常场景

| 场景编号 | 场景名称 | 前置条件 | 操作步骤 | 预期结果 | 状态变化 |
|----------|----------|----------|----------|----------|----------|
| N-001 | 启动检测到新版本 | App 版本 < 服务端版本，未标记已升级 | 1. 用户打开 App 2. 启动完成后发起版本检测 3. 检测到新版本 | 弹出升级弹窗，显示版本号+更新日志 | 无 |
| N-002 | 启动未检测到新版本 | App 版本 >= 服务端版本 | 1. 用户打开 App 2. 启动完成后发起版本检测 3. 无新版本 | 无弹窗，用户正常使用 | 无 |
| N-003 | 已升级后启动 | 点击过「立即更新」，同会话 `hasUpgraded = true` | 1. 用户再次启动（刷新浏览器重置标记） | 再次弹出升级弹窗（标记随浏览器刷新清除） | 无 |
| N-004 | 点击「立即更新」 | 升级弹窗已展示 | 1. 点击「立即更新」 2. 跳转系统浏览器打开 APK 下载 URL | 弹窗关闭，跳转浏览器下载 | `hasUpgraded = true` |
| N-005 | 点击「稍后提醒」 | 升级弹窗已展示 | 1. 点击「稍后提醒」 2. 关闭弹窗 | 弹窗关闭 | 无（不标记已升级，下次检测仍弹） |

#### 4.1.3 异常场景

| 场景编号 | 异常类型 | 触发条件 | 系统行为 | 用户感知 |
|----------|----------|----------|----------|----------|
| E-001 | 网络异常 | 版本检测接口请求超时/无网络 | 静默失败，不弹窗，不打扰用户 | 无感知 |
| E-002 | 接口异常 | 接口返回非预期格式（如 code !== 0） | 静默失败，不弹窗 | 无感知 |
| E-003 | 版本号异常 | 服务端返回版本号格式非法（非 semver） | 静默失败，记录日志，不弹窗 | 无感知 |
| E-004 | 下载链接为空 | 新版本无 downloadUrl | 弹窗展示更新日志，但无「立即更新」按钮或按钮置灰 | 看到更新信息但无法下载，Toast 提示「下载链接暂不可用」 |
| E-005 | 浏览器无法打开 | 设备无浏览器/系统限制 | 弹窗关闭，底部 Toast 提示「已复制下载链接到剪贴板」 | 手动粘贴到其他浏览器下载 |

#### 4.1.4 边界条件

| 条件项 | 最小值 | 最大值 | 默认值 | 超限处理 |
|--------|--------|--------|--------|----------|
| 弹窗频率 | — | 1次/天/版本 | 1次 | 无超限场景 |
| 版本号段数 | 2段 | 4段 | 3段 | 按从左到右逐段比较，缺少的段视为 0 |
| 更新日志长度 | 0 | 500字 | — | 超过 500 字截断展示，提供「查看全部」展开 |

#### 4.1.5 状态流转

```
App启动 → 请求版本接口 → 
  ├─ 失败/无网络 → 静默结束
  ├─ 已是最新 → 静默结束
  ├─ hasUpgraded = true → 静默结束
  └─ 有新版本 → 弹出升级弹窗 → 
        ├─ 立即更新 → 跳转浏览器 + hasUpgraded = true
        └─ 稍后提醒 → 关闭弹窗（不标记）
```

### 4.2 手动检测（关于页面）

#### 4.2.1 功能概述
- 用户在关于页面点击「版本更新」按钮
- 若 `hasUpgraded = true`，直接 Toast「当前已是最新版本」不请求接口
- 否则发起版本检测请求
- 有新版弹升级弹窗，无新版 Toast 提示「当前已是最新版本」

#### 4.2.2 正常场景

| 场景编号 | 场景名称 | 前置条件 | 操作步骤 | 预期结果 | 状态变化 |
|----------|----------|----------|----------|----------|----------|
| N-006 | 手动检测到新版本 | 进入关于页面，未标记已升级 | 1. 点击「版本更新」2. 加载中 3. 检测到新版本 | 弹出升级弹窗（同 N-001 弹窗） | 无 |
| N-007 | 手动检测无新版本 | App 已是最新 | 1. 点击「版本更新」2. 加载中 3. 无新版本 | Toast：「当前已是最新版本」 | 无 |
| N-008 | 已升级后手动检测 | 已点击过「立即更新」，`hasUpgraded = true` | 1. 点击「版本更新」 | 不请求接口，直接 Toast：「当前已是最新版本」 | 无 |

#### 4.2.3 异常场景

| 场景编号 | 异常类型 | 触发条件 | 系统行为 | 用户感知 |
|----------|----------|----------|----------|----------|
| E-007 | 网络异常 | 手动检测时无网络 | 结束 loading，Toast 提示 | 「网络异常，请稍后重试」 |
| E-008 | 接口异常 | 接口返回异常 | 结束 loading，Toast 提示 | 「检测失败，请稍后重试」 |

### 4.3 关于页面

#### 4.3.1 功能概述
- 独立的关于页面，路由 `/about`
- 展示 App 信息 + 版本更新入口 + 法律条款链接

#### 4.3.2 页面内容

| 区域 | 内容 |
|------|------|
| App 信息 | App Logo + 名称「CareCam Pro」+ 当前版本号（如 `v1.0.0`） |
| 版本更新 | 「版本更新」按钮，带右箭头，点击触发手动检测 |
| 法律信息 | 用户协议、隐私政策（外部链接跳转） |

### 4.4 升级弹窗

#### 4.4.1 弹窗内容

| 元素 | 说明 |
|------|------|
| 弹窗类型 | `van-popup` 居中弹出，圆角卡片 |
| 头部 | 标题「发现新版本」+ 版本号（如 `v1.2.0`） |
| 内容 | 更新日志文本（支持换行），可滚动 |
| 底部按钮 | 「稍后提醒」（次要）+「立即更新」（主要） |

## 六、推荐方案确认

基于用户确认和业界最佳实践，以下为本次需求的推荐方案：

| 问题 | 推荐方案 | 理由 |
|------|----------|------|
| 下载方式 | 跳转系统浏览器下载 APK | CareCam Pro 侧载分发，无应用商店依赖 |
| 弹窗按钮 | 「稍后提醒」+「立即更新」 | 非强制升级，给用户选择权 |
| 版本比较规则 | 语义化版本（semver），逐段比较 | 行业标准，避免字符串比较的坑 |
| 版本接口格式 | `GET /api/app/version` → `{ version, downloadUrl, releaseNotes, forceUpdate }` | 扩展性好，后续支持强制升级 |
| 会话标记 | `hasUpgraded` 模块级 ref，同会话内点击「立即更新」后不再弹窗，刷新浏览器即重置 | 简单可靠，无需后端参与，演示友好 |
| 关于页面内容 | Logo + 名称 + 版本号 + 版本更新 + 用户协议/隐私政策链接 | 信息清晰，不含冗余 |
| 接口失败处理 | 自动检测静默失败，手动检测 Toast 提示 | 自动不打扰用户，手动给反馈 |
