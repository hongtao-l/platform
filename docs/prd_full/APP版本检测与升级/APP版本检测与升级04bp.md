## 一、核心指标体系

### 1.1 指标总览

| 序号 | 指标名称 | 指标类型 | 计算方式 | 目标值 | 监控周期 |
|------|----------|----------|----------|--------|----------|
| 1 | 升级弹窗曝光率 | 行为 | 弹窗展示次数 / App启动次数 | ≥ 30%（有新版时） | 日 |
| 2 | 升级转化率 | 业务 | 点击「立即更新」次数 / 弹窗展示次数 | ≥ 40% | 日 |
| 3 | 升级忽略率 | 行为 | 点击「稍后提醒」次数 / 弹窗展示次数 | ≤ 60% | 日 |
| 4 | 手动检测使用率 | 行为 | 手动检测触发次数 / App启动次数 | ≥ 5% | 周 |
| 5 | 版本检测成功率 | 质量 | 检测成功次数 / 检测总次数 | ≥ 99% | 日 |
| 6 | 新版覆盖率 | 业务 | 新版活跃用户数 / 总活跃用户数 | 跟版本节奏 | 周 |

### 1.2 指标详细说明

**升级弹窗曝光率**
- 业务含义：有新版本时，升级弹窗实际展示的比例。反映自动检测通道是否正常工作。
- 为何选择：这是版本升级的入口漏斗第一步，曝光率低说明检测逻辑或接口有问题。
- 数据波动：曝光率突降需排查版本接口是否异常；突增需确认是否误将旧版判为新版。

**升级转化率**
- 业务含义：看到弹窗后选择「立即更新」的用户比例。衡量升级提示的吸引力。
- 为何选择：直接反映版本升级功能的核心价值——促使用户完成升级。
- 数据波动：转化率过低需评估更新日志文案是否清晰、下载链接是否可用。

**手动检测使用率**
- 业务含义：用户在关于页面主动点击「版本更新」的比例。
- 为何选择：衡量用户对版本更新的主动关注度，辅助判断是否需要优化入口引导。
- 数据波动：使用率持续低增长可考虑在设置页增加红点提示。

**版本检测成功率**
- 业务含义：版本检测接口请求成功的比例。
- 为何选择：质量底线指标，检测失败直接影响升级触达。
- 数据波动：成功率下降需排查服务端接口或网络链路。

**新版覆盖率**
- 业务含义：发布新版本后，活跃用户中已升级到新版的比例。
- 为何选择：衡量版本推广效果，辅助决定是否关闭旧版兼容逻辑。
- 数据波动：覆盖率增长慢可能意味着下载链接有问题或用户升级意愿低。

## 二、埋点方案

### 2.1 事件清单

| 事件ID | 事件名称 | 触发时机 | event_type | 优先级 |
|--------|----------|----------|------------|--------|
| app_version_check_auto | 启动自动检测 | App启动完成后，自动发起版本检测请求时 | 0 | P0 |
| app_version_check_manual | 手动检测 | 用户在关于页面点击「版本更新」时 | 0 | P0 |
| app_upgrade_popup_show | 升级弹窗展示 | 检测到新版本，升级弹窗弹出时 | 0 | P0 |
| app_upgrade_click_update | 点击立即更新 | 用户在弹窗中点击「立即更新」 | 1 | P0 |
| app_upgrade_click_dismiss | 点击稍后提醒 | 用户在弹窗中点击「稍后提醒」 | 0 | P0 |
| app_version_check_fail | 版本检测失败 | 版本检测接口请求失败或返回异常 | 2 | P1 |
| app_version_is_latest | 检测结果已是最新 | 版本检测接口正常返回且当前已是最新版本 | 0 | P1 |
| app_upgrade_download_fail | 下载跳转失败 | 无 downloadUrl 或浏览器无法打开 | 2 | P1 |
| app_about_page_view | 关于页面浏览 | 用户进入关于页面 | 0 | P2 |

| 参数 | 类型 | 必填 | 说明 | 示例值 |
|------|------|------|------|------|
| event_type | String | 是 | 0=普通事件，1=额外参数事件，2=错误事件 | "0" |
| event_id | String | 是 | 事件ID | "app_upgrade_popup_show" |
| event_time | Int64 | 是 | 事件发生时间戳(ms) | 1716192000000 |
| user_id | String | 是 | 用户唯一标识 | "usr_123456" |
| session_id | String | 是 | 会话ID | "sess_abc123" |
| app_id | String | 是 | 应用ID | "carecam_pro" |
| app_version | String | 是 | 当前App版本号 | "1.0.0" |
| brand | String | 是 | 手机品牌 | "xiaomi" |
| os_type | String | 是 | 系统类型 | "Android" |
| os_version | String | 是 | 手机系统版本 | "14.0" |
| company_id | String | 是 | 用户的从属企业ID | "0000213ed0cdb8bc" |
| country | String | 是 | 国家 | "CN" |
| city | String | 是 | 城市 | "" |

### 2.3 业务参数（按事件）

**app_version_check_auto**：

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| has_upgraded | String | 是 | 当前会话是否已标记升级（"true"/"false"），决定是否跳过检测 |

**app_version_check_manual**：

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| has_upgraded | String | 是 | 当前会话是否已标记升级 |
| from_page | String | 是 | 来源页面标识，固定 "about" |

**app_upgrade_popup_show**：

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| current_version | String | 是 | 当前App版本号 |

| trigger_type | String | 是 | 触发来源："auto"/"manual" |
| has_download_url | String | 是 | 是否有下载链接（"true"/"false"） |

**app_upgrade_click_update**：

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| current_version | String | 是 | 当前App版本号 |
| target_version | String | 是 | 目标升级版本号 |
| trigger_type | String | 是 | 触发来源："auto"/"manual" |
| download_url | String | 是 | APK下载链接（脱敏） |

**app_upgrade_click_dismiss**：

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| current_version | String | 是 | 当前App版本号 |
| target_version | String | 是 | 目标升级版本号 |
| trigger_type | String | 是 | 触发来源："auto"/"manual" |

**app_version_check_fail**：

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| error_type | String | 是 | 错误类型："network"/"api_error"/"invalid_version" |
| error_msg | String | 否 | 错误详情（截断至200字符） |
| trigger_type | String | 是 | 触发来源："auto"/"manual" |

**app_version_is_latest**：

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| current_version | String | 是 | 当前App版本号 |
| trigger_type | String | 是 | 触发来源："auto"/"manual" |

**app_upgrade_download_fail**：

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| fail_reason | String | 是 | 失败原因："no_download_url"/"browser_unavailable" |
| target_version | String | 是 | 目标升级版本号 |

**app_about_page_view**：

无额外业务参数（仅公共参数）。

### 2.4 上报方式

```
POST /api/app/event
```

### 2.5 去重策略

| 场景 | 策略 |
|------|------|
| 自动检测重复触发 | 客户端以 session_id + event_id 去重，同会话仅上报一次 |
| 弹窗展示重复上报 | 同会话同版本号弹窗仅上报一次 |
| 手动检测快速连点 | 客户端 2s 内同一事件去重 |

### 2.6 数据校验

| 校验项 | 规则 | 异常处理 |
|--------|------|----------|
| event_type | 必须为 0/1/2 | 丢弃并告警 |
| app_version | 必须为合法 semver 格式 | 写入但标记脏数据 |
| user_id | 非空字符串 | 丢弃（无法关联用户） |
| event_time | 与服务器时间偏差 < 24h | 偏差 > 1h 写入但标记 |

### 3.3 报表需求

| 报表名称 | 报表类型 | 数据维度 | 刷新频率 | 接收人 | 备注 |
|----------|----------|----------|----------|--------|------|
| 版本升级日报 | 日报 | 按版本号 × 按天 | 每日 09:00 | 产品经理、运营 | 含前一日各项指标 |
| 版本覆盖率周报 | 周报 | 按版本号 × 按周 | 每周一 09:00 | 产品经理、技术负责人 | 含覆盖率趋势图 |
| 异常告警通知 | 实时 | 按错误类型 | 触发即报 | 技术负责人、值班 | 检测成功率 < 95% 时触发 |

### 3.4 告警规则

| 告警名称 | 触发条件 | 告警级别 | 通知方式 | 接收人 |
|----------|----------|----------|----------|--------|
| 检测成功率骤降 | 5分钟内检测成功率 < 95% | P1 | 站内 + 推送 | 技术负责人 |
| 检测接口不可用 | 连续3分钟成功率 = 0% | P0 | 站内 + 推送 + 邮件 | 值班 + 技术负责人 |
| 无下载链接占比高 | 弹窗展示中 has_download_url=false 占比 > 10% | P2 | 站内 | 产品经理 |
| 升级转化率异常低 | 当日升级转化率 < 20%（有新版时） | P2 | 站内 | 产品经理 + 运营 |

## 四、数据字典

### 4.1 事件枚举

| 事件ID | 含义 | event_type |
|--------|------|------------|
| app_version_check_auto | App启动自动发起版本检测 | 0 |
| app_version_check_manual | 用户在关于页手动触发检测 | 0 |
| app_upgrade_popup_show | 升级弹窗展示 | 0 |
| app_upgrade_click_update | 用户点击「立即更新」 | 1 |
| app_upgrade_click_dismiss | 用户点击「稍后提醒」 | 0 |
| app_version_check_fail | 版本检测失败 | 2 |
| app_version_is_latest | 检测结果已是最新版本 | 0 |
| app_upgrade_download_fail | 下载跳转失败 | 2 |
| app_about_page_view | 关于页面浏览 | 0 |

### 4.2 参数枚举值

**trigger_type**：

| 值 | 含义 |
|----|------|
| auto | 启动自动检测触发 |
| manual | 手动点击「版本更新」触发 |

**error_type**：

| 值 | 含义 |
|----|------|
| network | 网络异常（超时/无网络） |
| api_error | 接口返回非预期格式（code !== 0） |
| invalid_version | 服务端返回版本号格式非法 |

**fail_reason**：

| 值 | 含义 |
|----|------|
| no_download_url | 新版本无 downloadUrl |
| browser_unavailable | 设备无法打开浏览器 |
