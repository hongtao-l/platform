## 一、核心指标体系

### 1.1 指标总览

| 序号 | 指标名称 | 指标类型 | 计算方式 | 目标值 | 监控周期 |
|---|---|---|---|---|---|
| M-01 | 配置开启率 | 业务 | 已开启预唤醒的产品数 ÷ 适用产品数（电池供电机型） | ≥ 50% | 周 |
| M-02 | 单设备日均唤醒次数 | 行为 | 预唤醒触发次数 ÷ 活跃设备数 | ≤ 6 次/天 | 日 |
| M-03 | 预唤醒成功率 | 质量 | 唤醒成功次数 ÷ 发起次数 | ≥ 90% | 日 |
| M-04 | 首帧耗时（开启预唤醒） | 质量 | 进入设备到首帧渲染的 P50 | ≤ 3 秒 | 日 |
| M-05 | 首帧耗时（未开启） | 质量 | 同上，对照组 | 基线值 | 日 |
| M-06 | 设备日均耗电增量 | 业务 | 开启产品设备日耗电 ÷ 未开启产品设备日耗电 | ≤ 1.3 倍 | 周 |

### 1.2 指标详细说明

**M-02 单设备日均唤醒次数（最关键的护栏指标）**

- 业务含义：用户每天进首页触发多少次唤醒。数字越高，设备越费电。
- 为什么选它：预唤醒的本质是"用续航换体验"，这个指标直接体现代价。
- 波动原因：用户打开频次高、冷却期过短、首页存在重复触发逻辑。**应对**：超过 10 次/天需排查是否冷却期失效。

**M-06 耗电增量**

- 业务含义：开启预唤醒产品的设备，日均耗电比未开启产品高多少。
- 波动原因：唤醒频次、设备网络类型（4G 更耗电）、固件休眠策略。**应对**：超过 1.5 倍暂停推广并回滚配置。

**M-04 vs M-05 首帧耗时对比**

- 业务含义：这个功能的唯一价值就体现在这两个数的差上。
- 若差值 < 1 秒，说明用户实际收益很小，应考虑下线或改方案。

## 二、埋点方案

### 2.1 事件清单

| 事件ID | 事件名称 | 触发时机 | event_type | 优先级 |
|---|---|---|---|---|
| `pre_wake_view` | 查看设备预唤醒配置 | 默认配置 Tab 渲染完成 | 0 | P1 |
| `pre_wake_toggle` | 切换设备预唤醒开关 | 开关值变更 | 1 | P0 |
| `pre_wake_disabled_hint` | 开关置灰提示展示 | 产品不支持远程唤醒时渲染置灰 | 2 | P1 |
| `pre_wake_trigger` | 触发一次预唤醒 | APP 对某设备下发唤醒指令 | 1 | P0 |
| `pre_wake_result` | 预唤醒结果 | 唤醒成功或失败 | 1 | P0 |
| `pre_wake_skip` | 跳过预唤醒 | 因在线/冷却期跳过 | 1 | P1 |
| `pre_wake_first_frame` | 首帧耗时上报 | 设备首帧渲染完成 | 1 | P0 |

> 前 3 个为管理后台埋点，后 4 个为 APP 端埋点。

### 2.2 公共参数（所有事件必带）

| 参数 | 类型 | 必填 | 说明 | 示例值 |
|---|---|---|---|---|
| event_type | String | 是 | 0=普通事件，1=额外参数事件，2=错误事件 | "1" |
| event_id | String | 是 | 事件ID | "pre_wake_toggle" |
| event_time | Int64 | 是 | 事件发生时间戳(ms) | 1795000000000 |
| user_id | String | 是 | 用户唯一标识 | "usr_123456" |
| session_id | String | 是 | 会话ID | "sess_abc123" |
| app_id | String | 是 | 应用ID | "iot_platform" |
| app_version | String | 是 | 应用版本号 | "1.4.2" |
| brand | String | 是 | 手机品牌 | "apple" |
| os_type | String | 是 | 系统类型 | "iOS" |
| os_version | String | 是 | 手机系统版本 | "17.0" |
| company_id | String | 是 | 用户从属企业ID | "0000213ed0cdb8bc" |
| country | String | 是 | 国家 | "CN" |
| city | String | 是 | 城市 | "深圳" |

> 公共参数固定 13 项，不可增减。

### 2.3 业务参数（按事件）

**pre_wake_view**（event_type = 0）

无业务参数。

**pre_wake_toggle**

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| product_id | String | 是 | 产品ID |
| enable | String | 是 | 切换后的值，0=关闭 / 1=开启 |
| previous_enable | String | 是 | 切换前的值 |

**pre_wake_disabled_hint**（event_type = 2）

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| product_id | String | 是 | 产品ID |
| reason | String | 是 | 固定值 `no_remote_wake` |

**pre_wake_trigger**

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| device_id | String | 是 | 设备ID |
| product_id | String | 是 | 产品ID |
| network_type | String | 是 | `wifi` / `4g` / `wired` |
| battery_level | Int | 是 | 触发时设备电量，无电池传 -1 |
| scene | String | 是 | 触发场景：`home_enter` / `detail_back` |

**pre_wake_result**

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| device_id | String | 是 | 设备ID |
| product_id | String | 是 | 产品ID |
| success | String | 是 | 1=成功 / 0=失败 |
| cost_ms | Int | 是 | 唤醒耗时，单位毫秒 |
| fail_reason | String | 否 | timeout / offline / auth_fail |

**pre_wake_skip**

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| device_id | String | 是 | 设备ID |
| product_id | String | 是 | 产品ID |
| skip_reason | String | 是 | `online` / `cooling` / `limit` |

**pre_wake_first_frame**

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| device_id | String | 是 | 设备ID |
| product_id | String | 是 | 产品ID |
| pre_wake_hit | String | 是 | 本次进入是否命中预唤醒，1/0 |
| first_frame_ms | Int | 是 | 从点击设备到首帧渲染的耗时 |

### 2.4 上报方式

```
POST /api/{module}/event
```

### 2.5 去重策略

| 场景 | 策略 |
|---|---|
| `pre_wake_view` | 同一会话内同一产品只上报一次 |
| `pre_wake_trigger` | 每台设备每次下发都上报，不去重（用于统计频次） |
| `pre_wake_skip` | 同一设备同一会话内按原因合并，每种原因最多一次 |
| `pre_wake_first_frame` | 每次进入设备详情上报一次 |

### 2.6 数据校验

| 校验项 | 规则 | 异常处理 |
|---|---|---|
| success / pre_wake_hit | 取值必须为 0 或 1 | 丢弃该字段 |
| cost_ms / first_frame_ms | 0 ~ 120000 | 越界丢弃，计入脏数据 |
| battery_level | -1 ~ 100 | 越界丢弃 |
| skip_reason | 在枚举内 | 非法值归入 `unknown` |
| scene | 在枚举内 | 非法值归入 `unknown` |

## 三、数据看板

### 3.1 看板概览

| 项 | 内容 |
|---|---|
| 看板名称 | 设备预唤醒效果看板 |
| 看板用途 | 评估功能采用度、体验收益与耗电代价 |
| 目标人群 | 产品经理、运营、研发 |

### 3.2 看板布局

```
区域 1：核心指标卡片区
- M-01 配置开启率（大字 + 环比）
- M-03 预唤醒成功率
- M-02 单设备日均唤醒次数（红色高亮阈值 10）
- M-04 / M-05 首帧耗时对比（并列两个大数 + 差值）

区域 2：趋势与结构
- 折线图：日均唤醒次数 / 首帧耗时 按周趋势（双轴）
- 柱状图：按网络类型（wifi / 4g）的成功率对比
- 饼图：跳过原因分布（online / cooling / limit）

区域 3：明细表格区
- 列：产品ID、产品名称、开启状态、活跃设备数、日均唤醒次数、成功率、P50 首帧耗时
- 筛选：按产品、网络类型、是否命中预唤醒
- 排序：日均唤醒次数降序（默认）

区域 4：异常下钻
- 唤醒失败明细：设备ID、失败原因、发生时间
- 高频唤醒 Top：日唤醒 > 20 次的设备列表
```

### 3.3 报表需求

| 报表名称 | 报表类型 | 数据维度 | 刷新频率 | 接收人 | 备注 |
|---|---|---|---|---|---|
| 预唤醒效果周报 | 周报 | 产品 / 网络类型 | 每周一 | 产品、运营 | 含首帧耗时对比 |
| 高频唤醒设备日报 | 日报 | 设备 | 每日 | 研发 | 排查冷却期或重复触发 |

### 3.4 告警规则

| 告警名称 | 触发条件 | 告警级别 | 通知方式 | 接收人 |
|---|---|---|---|---|
| 唤醒成功率异常 | 当日成功率 < 70% | P1 | 企业微信 | 研发 |
| 单设备唤醒次数异常 | 单设备日唤醒 > 30 次 | P1 | 企业微信 | 研发、产品 |
| 首帧无改善 | 开启 vs 未开启差值 < 500ms 且样本 ≥ 1000 | P2 | 邮件 | 产品 |

## 四、数据字典

| 字段 | 取值 | 含义 |
|---|---|---|
| enable / previous_enable | 0 / 1 | 关闭 / 开启 |
| success | 0 / 1 | 失败 / 成功 |
| pre_wake_hit | 0 / 1 | 未命中 / 命中预唤醒 |
| network_type | wifi / 4g / wired | 设备联网方式 |
| scene | home_enter / detail_back | 进入首页 / 从详情返回 |
| skip_reason | online / cooling / limit | 已在线 / 冷却期 / 限流 |
| fail_reason | timeout / offline / auth_fail | 超时 / 离线 / 鉴权失败 |
| event_type | 0 / 1 / 2 | 普通 / 业务参数 / 错误事件 |

### 事件与异常场景对应

| 需求文档异常编号 | 对应埋点 |
|---|---|
| E-001 能力不满足 | `pre_wake_disabled_hint` |
| E-005 唤醒失败 | `pre_wake_result`（success=0） |
| E-006 并发限流 | `pre_wake_skip`（skip_reason=limit） |
| N-008 设备已在线 | `pre_wake_skip`（skip_reason=online） |
| N-009 冷却期 | `pre_wake_skip`（skip_reason=cooling） |
