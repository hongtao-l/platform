## 一、业务背景

### 业务场景
- 我们是 IoT 设备（IPC 监控为核心、全品类扩展）厂商的定制 APP 服务方，B2B2C 模式，服务厂商、运营商及国内外 C 端用户。
- 为不同客户定制 APP，但**所有客户共用同一套后台服务、数据库、SDK**。
- APP 采用三层架构：**业务层 / 数据层 / SDK 层**；客户定制**只变更业务层（UI、交互等）**。

### 业务层内部结构（本次新增关键约定）
业务层进一步分为两类：
- **APP业务功能**：APP 完整业务基础功能，**所有客户一致、稳定**。
- **设备功能**：随接入设备类型扩展，**每个设备类型功能不一致，由物模型驱动**。

### 用户痛点
- 传统定制开发：每个客户都要重复开发业务层，效率低、成本高、交付慢。
- 视觉设计（Figma）与行为逻辑（交互/状态/边界/异常）之间缺一条统一的开发基线，AI 无法稳定、可复用地产出代码。
- 设备类型众多、功能各异，缺少一套「物模型驱动」的统一规则来生成设备操作界面。

### 产品目标
1. 产出一份「APP 通用需求文档」，作为 **AI 结合 Figma 设计稿快速开发业务层** 的统一基线。
2. 明确三层架构边界：**数据层 + SDK 层复用**（引用已有文档，不重复描述），**业务层由 AI 按「本文档 + Figma」生成**。
3. 业务层二分为「APP业务功能」+「设备功能」：APP业务功能穷举行为逻辑；设备功能定义「物模型驱动」的通用框架与显隐规则。
4. 确保 AI 拿到文档后无需再追问业务逻辑。

## 二、名词解释

| 术语 | 说明 |
|------|------|
| 业务层 | APP 的 UI 页面、组件、交互逻辑；客户定制的对象；由 AI 生成 |
| APP业务功能 | 业务层中的稳定部分：启动页、登录注册、首页、消息、我的；所有客户一致 |
| 设备功能 | 业务层中的可变部分：随设备类型扩展，由物模型驱动，按「设备卡片/控制面板/设备设置」三模块组织 |
| 数据层 | 后台服务 + 数据库；所有客户共用；本文档引用已有接口文档，不重复描述 |
| SDK层 | 设备连接、推流、回放、推送等底层能力；所有客户共用；本文档引用已有 SDK 文档 |
| Figma MCP | 将 Figma 设计稿接入 AI 的通道，AI 通过它读取设计稿 |
| Figma 纯视觉 | Figma 只承载颜色/布局/组件样式/图标；交互、状态、边界、异常、数据字段均由本文档定义 |
| 通用需求文档 | 本文档最终产物：AI 消费的行为逻辑基线 |
| 物模型 | 设备功能属性（Property）/ 动作指令（Action）/ 告警事件（Event）的标准化定义 |
| 物模型驱动 | 设备功能的操作项及其显隐由物模型字段控制，具体规则由技术文档决定 |
| 设备卡片 | 设备功能的三大模块之一：设备在列表/详情中的展示卡片 |
| 控制面板 | 设备功能的三大模块之一：设备的操作/控制界面 |
| 设备设置 | 设备功能的三大模块之一：设备的参数配置界面 |
| 设备类型 | 接入的设备品类，如摄像机、NVR、喂食器等；当前仅摄像机 |

## 三、功能范围

### 3.1 业务层二分类（核心架构）

```
业务层
├── APP业务功能（稳定，所有客户一致，本文档穷举行为逻辑）
│   ├── 启动页
│   ├── 登录/注册
│   ├── 首页
│   ├── 消息
│   └── 我的
└── 设备功能（物模型驱动，按设备类型扩展，本文档定义通用框架+显隐规则）
    ├── 摄像机类型 ── 设备卡片 / 控制面板 / 设备设置
    └── [未来扩展：NVR、喂食器、门铃、打猎相机…]
```

|------|------|--------|--------|------|
| 1 | 启动页 | 启动展示、跳转 | P1 | 品牌展示 + 登录态判断 |

- **当前设备类型**：摄像机类型（功能点待补充，见「待确认问题 Q5」）。

| 设备类型 | 设备卡片 | 控制面板 | 设备设置 | 状态 |
|---------|---------|---------|---------|------|
| 摄像机 | 设备名/在线状态/画面封面/分享标签/消息红点/快捷入口 | 实时画面/清晰度/声音/录制/截图/对讲/PTZ/预置位/隐私/报警/声光报警/移动追踪/双向留言/全屏/WIFI | 概况/侦测(含AI人形)/通知/画面/音频/存储(含云存开通)/云台/灯光/电池/分享/删除 | 详见 4.7（AI 草拟，待确认） |

### 3.4 不做 / 暂不做的功能（明确边界）

| 功能 | 原因 | 后续计划 |
|------|------|---------|
| 数据层 / SDK 层的具体实现 | 已有文档，本文档仅引用 | 引用 `docs/prd_dec/platform_prd.md`、`docs/draft/物模型定义.md`、`docs/draft/能力库.md` 等（待确认最终清单） |
| 视觉样式定义（颜色/字号/间距） | 由 Figma 承载 | Figma MCP 读取 |

### 3.5 三层架构边界（本文档核心约定）

```
┌─────────────────────────────────────────────┐
│ 业务层（本文档定义行为逻辑，AI 按 Figma 生成）│
│   ├─ APP业务功能（稳定，穷举行为逻辑）        │
│   └─ 设备功能（物模型驱动，通用框架+显隐规则）│
├─────────────────────────────────────────────┤
│ 数据层（后台服务+数据库，复用，引用接口文档） │
├─────────────────────────────────────────────┤
│ SDK层（设备连接/推流/回放/推送，复用，引用SDK文档）│
└─────────────────────────────────────────────┘
```

- **AI 的工作边界**：只生成业务层（页面 / 组件 / 交互）；数据层、SDK 通过既有封装调用。
- **Figma 的分工**：纯视觉（颜色 / 布局 / 组件样式 / 图标）；本文档承载交互 / 状态 / 边界 / 异常 / 数据字段。
- **本文档的分工**：承载「稳定不变」的行为逻辑；客户差异只体现在 Figma 的视觉上。

## 四、场景穷举分析

> 说明：以下按「行为逻辑」穷举，视觉实现一律交由 Figma。异常场景至少覆盖「网络异常 / 数据为空 / 权限不足」三类。

### 4.0 全局通用规范（所有模块共同遵守）

#### 4.0.1 功能概述
- 定义贯穿全 APP 的交互与状态规范，AI 生成任意页面时默认遵守，无需逐页重复描述。

#### 4.0.2 通用状态
| 状态 | 触发条件 | 系统行为 |
|------|---------|---------|
| 加载中 | 接口请求未返回 | 显示 loading / 骨架屏 |
| 空数据 | 列表无内容 | 空态占位图 + 引导文案 |
| 错误 | 接口异常 | 错误页 / Toast + 重试按钮 |
| 成功 | 操作完成 | Toast 反馈 |

#### 4.0.3 通用交互规范
- i18n：所有文案预留中英文结构，按语言变量切换。
- 自适应：内容限制 375px 宽度（H5 原型），适配常规分辨率。
- 交互反馈：所有按钮/操作有基础反馈（点击态、loading、成功提示）。
- 兜底：杜绝白屏、控制台报错，所有异常有兜底 UI。

#### 4.0.4 边界条件
| 条件项 | 说明 |
|--------|------|
| 网络 | 无网/弱网时所有请求统一兜底，恢复后自动重试或手动重试 |
| 权限 | 未登录 / 未激活 / 未开通服务 三类权限异常统一引导 |

### 4.6 设备功能（物模型驱动）

#### 4.6.1 功能概述
- 目的：面向设备类型的操作与配置，随设备类型扩展。
- 前置条件：已登录，已绑定设备。

#### 4.6.2 通用框架（三大模块）
| 模块 | 定位 | 说明 |
|------|------|------|
| 设备卡片 | 设备在列表/详情中的展示 | 状态、快照、快捷入口 |
| 控制面板 | 设备的操作/控制界面 | 操作项由物模型提供 |
| 设备设置 | 设备的参数配置界面 | 配置项由物模型提供 |

> 三大模块的功能归属由**业务与用户体验**决定；物模型（Property/Action/Event）仅提供数据来源与显隐控制，不硬性约束功能点归入哪个模块，可能存在交叉或重复。

#### 4.6.3 物模型驱动规则（核心）
| 规则编号 | 规则 | 说明 |
|---------|------|------|
| R-601 | 操作项来源 | 所有设备功能操作项均来自物模型定义 |
| R-602 | 操作项显隐 | 操作项显隐由物模型字段控制，具体规则由技术文档决定 |
| R-603 | 模块归属 | 功能点归入哪个模块由业务与用户体验决定；物模型类型（Property/Action/Event）仅作数据来源参考，不约束 UI 组织，可能存在交叉或重复 |

#### 4.6.4 正常场景（通用）
| 场景编号 | 场景名称 | 操作步骤 | 预期结果 |
|---------|---------|---------|---------|
| N-601 | 进入控制面板 | 点击设备卡片 | 按物模型渲染操作项 |
| N-602 | 执行设备操作 | 点击操作项 | 下发指令（Action），设备响应 |
| N-603 | 修改设备设置 | 修改设置项 | 保存属性（Property），生效 |

#### 4.6.5 异常场景（通用）
| 场景编号 | 异常类型 | 触发条件 | 系统行为 |
|---------|---------|---------|---------|
| E-601 | 设备离线 | 操作离线设备 | 操作项置灰或提示离线 |
| E-602 | 网络异常 | 指令下发失败 | Toast + 重试 |
| E-603 | 数据异常 | 物模型字段缺失/未定义 | 该操作项隐藏（按 R-602） |

#### 4.6.6 摄像机类型功能点
- 摄像机类型的功能点详见 4.7 节（AI 基于安防摄像机通用能力草拟，待用户确认，最终以物模型技术文档为准）。

## 五、跨模块联动分析

- **登录态联动**：登录/退出/注销 影响 首页、消息、我的 及所有设备功能的可用性。
- **设备列表 → 设备功能联动**：首页设备卡片点击进入对应设备类型的控制面板/详情；设备类型决定渲染的模块与操作项。
- **物模型联动**：设备功能的操作项显隐、模块归属统一由物模型字段驱动，AI 需按「设备类型 → 物模型 → 操作项」链路渲染。
- **消息联动**：消息详情可能跳转至对应设备类型的功能页（待确认）。
