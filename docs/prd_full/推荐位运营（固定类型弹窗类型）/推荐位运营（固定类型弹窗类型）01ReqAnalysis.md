## 一、业务背景

### 业务场景

当前推荐位运营仅支持「弹窗类型」——App 启动后按漏斗层级依次弹窗展示套餐推荐。现需新增「固定类型」推荐位，在 App 页面固定位置（如首页底部）持续展示推荐内容，用户可手动关闭，关闭后进入冷却期，冷却期结束后若用户仍命中策略则重新展示。

### 用户痛点
- 弹窗类型为打断式触达，部分场景下需要非打断的持续曝光
- 缺乏固定位置（如首页底部）的常驻推荐能力
- 运营希望有两种触达方式可选，覆盖不同用户偏好

### 产品目标
- 新增固定类型推荐位，与弹窗类型完全独立，运营可按场景选择
- 固定类型展示位置通过编码约定（新增位置需发版），内容为套餐列表（1~5个，可排序）
- 固定类型支持用户手动关闭 + 冷却期（小时），关闭后同设备在冷却期内不再展示
- 固定类型点击行为：直接跳转订单确认页（支付流程）
- 弹窗类型和固定类型不互斥，可同时展示

## 二、名词解释

| 术语 | 说明 |
|------|------|
| 推荐位 | App 内展示套餐推荐的运营位置，如首页底部 |
| 弹窗类型（Popup） | 现有推荐类型，按漏斗层级弹窗展示，有弹窗间隔和冷却期 |
| 固定类型（Fixed） | 新增推荐类型，在页面固定位置持续展示，用户可手动关闭 |
| 推荐位位置编码 | 固定类型展示位置的唯一标识（如 `home_bottom`），前后端约定，新增需发版 |
| 冷却时间（固定类型） | 用户关闭固定推荐位后，再次展示前需等待的时间，以小时为单位 |
| 套餐列表（固定类型） | 固定类型展示的套餐集合，1~5 个，支持排序，按序展示 |
| 冷却期（弹窗类型） | 一轮漏斗展示完毕后暂停弹窗的静默时段，以天为单位 |
| 弹窗间隔 | 弹窗类型两次弹窗间的最小间隔，以小时为单位 |

## 四、场景穷举分析

- 推荐位策略页面顶部增加类型切换控件


### 4.3 APP端 — 固定推荐位展示与交互

#### 4.3.1 功能概述
- App 首页（或其他约定位置）展示固定推荐位
- 展示内容为策略配置的套餐列表（按排序展示）
- 用户可点击套餐跳转订单确认页，也可点关闭按钮关闭
- 关闭后进入冷却计时，冷却期内不展示

#### 4.3.2 正常场景

| 场景编号 | 场景名称 | 前置条件 | 操作步骤 | 预期结果 | 状态变化 |
|----------|----------|----------|----------|----------|----------|
| N-020 | APP展示固定推荐位 | 用户命中固定类型策略，位置为首页底部 | 1. 用户打开 App 2. App 拉取匹配策略 3. 在首页底部渲染固定推荐位 | 首页底部展示套餐列表（按配置排序） | 展示 |
| N-021 | 用户点击固定推荐位套餐 | 固定推荐位已展示 | 1. 用户点击某个套餐 2. 跳转订单确认页 | 订单确认页展示该套餐，预填套餐信息 | 页面跳转 |
| N-022 | 用户关闭固定推荐位 | 固定推荐位已展示 | 1. 用户点击关闭按钮（X） 2. 推荐位消失 | 推荐位隐藏，开始冷却计时 | 关闭 + 冷却开始 |
| N-023 | 冷却期内重新打开 App | 关闭固定推荐位后 1 小时，冷却时间设为 2 小时 | 1. 用户打开 App 2. App 拉取策略 | 固定推荐位不展示（仍在冷却期） | 无 |
| N-024 | 冷却期后重新打开 App | 关闭固定推荐位后 3 小时，冷却时间设为 2 小时 | 1. 用户打开 App 2. App 拉取策略 3. 用户仍命中该策略 | 固定推荐位重新展示 | 展示 |
| N-025 | 切换设备/清除缓存后 | 在设备 A 关闭推荐位后，换设备 B（或清除浏览器缓存）打开 App | 用户打开 App | 设备 B/清除缓存后冷却记录不存在，重新展示推荐位（冷却记录存储在本机） | 展示 |

#### 4.3.3 异常场景

| 场景编号 | 异常类型 | 触发条件 | 系统行为 | 用户感知 |
|----------|----------|----------|----------|----------|
| E-020 | 网络异常 | 拉取策略时无网络 | 不展示固定推荐位 | 无感知 |
| E-021 | 无匹配策略 | 用户不命中任何策略的投放条件 | 不展示固定推荐位 | 无感知 |
| E-022 | 位置编码不识别 | 服务端返回的位置编码 APP 端不支持 | 不展示该固定推荐位 | 无感知 |
| E-023 | 套餐列表为空 | 策略配置的套餐列表为空（后端数据异常） | 不展示该固定推荐位 | 无感知 |
| E-024 | 套餐下架/不可购买 | 推荐的套餐已下架 | 点击该套餐后跳转订单确认页 → 提示「该套餐暂不可购买」 | Toast 提示 |
| E-025 | 点击跳转失败 | 订单确认页路由异常 | Toast 提示 | 「跳转失败，请稍后重试」 |

#### 4.3.4 边界条件

| 条件项 | 最小值 | 最大值 | 默认值 | 说明 |
|--------|--------|--------|--------|------|
| 展示套餐数 | 1 | 5 | — | 按策略配置的排序展示 |
| 冷却时间 | 1小时 | 720小时 | — | 关闭后开始计时，存储在本机 localStorage |
| 冷却计时精度 | — | — | 关闭时间戳 + 冷却小时数 | 判定方式：当前时间 >= 关闭时间 + 冷却小时数 |
| 固定位展示宽度 | — | 全屏宽度 | — | 适配不同屏幕尺寸 |

#### 4.3.5 冷却计时存储设计

```
localStorage key: fixed_rec_cooldown_{strategy_id}
localStorage value: { "closedAt": 1716192000000 }
```

判定逻辑：
1. 读取 `fixed_rec_cooldown_{strategy_id}`
2. 若不存在 → 展示
3. 若存在 → 计算 `now >= closedAt + cooldownHours * 3600 * 1000`
   - 是 → 清除记录，展示
   - 否 → 不展示

| 关联模块 | 影响说明 |

| 用户分群组件 | 复用现有用户分群选择器 |
| 侧边栏菜单 | 不变（推荐位运营入口不变） |

### 5.2 APP端

| 关联模块 | 影响说明 |
|----------|----------|
| 首页 | 需在底部预留固定推荐位渲染区域 |
| 订单确认页 | 需接收推荐位跳转参数（套餐信息） |
| 策略拉取服务 | 需新增固定类型策略的拉取接口 |
| 本地存储 | 新增冷却时间记录的读写（localStorage） |
| 埋点上报 | 新增固定推荐位曝光/点击/关闭事件 |

### 5.3 与弹窗类型的关系

```
APP启动
  ├── 弹窗类型策略拉取 → 匹配 → 弹窗展示（按漏斗）
  └── 固定类型策略拉取 → 匹配 → 固定位展示（独立判断，不互斥）
       └── 冷却检查 → 冷却期 → 不展示
       └── 冷却检查 → 冷却已过 → 展示
```

两种类型完全独立运行，互不阻塞，可同时展示。

## 六、推荐方案确认

| 问题 | 推荐方案 | 理由 |
|------|----------|------|
| 类型切换 UI | 推荐位策略区域顶部 Tab 切换（弹窗类型 / 固定类型） | 同推荐位下两类策略独立管理，切换直观 |
