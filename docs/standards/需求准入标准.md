# APP 需求准入标准

> 版本：1.0
> 发布/更新日期：2026年10月27日
> 生效日期：2026年10月27日
> 适用范围：运营侧需求
> 守门人：产品负责人（本人终审）
> 承载工具：企业微信（收集表 / 多维表格 / 审批 / 群 / 微文档）

---

## 〇、30 秒速览

一个需求要进入排期，必须同时满足：

1. 提交了**完整的《需求方案书》**；
2. 通过**三项一票否决**：验收标准、埋点方案、合规评估；
3. 在周度准入评审会上**讲清楚三件事**：给谁解决什么问题 → 怎么衡量成功 → 不做会怎样。

缺任意一项 → **退回**，不进排期，记录在案。

---

## 一、目的

- **对需求方**：明确"什么样的需求才配进入排期"，减少无效沟通与反复返工。
- **对负责人**：把精力从"看人下菜"转为"看单子判准入"，每周 60 分钟完成全部决策。
- **对执行方**：拿到手的输入是完整的，不再边做边猜、边做边改。

---

## 二、核心原则

1. **准入是退回制，不是建议清单。** 标准写在单子上，缺项即退回，不因"着急"破例。
2. **运营出计划与设计，UI 出视觉执行。** 运营必须给出完整的流程、页面设计、状态与文案；UI 负责视觉与交互落地，不承担"帮运营想方案"的职责，可以提供建议。
3. **不能验证的需求不做。** 没有基线、没有口径、没有埋点的需求，等于上线后无法证明价值。
4. **能配置的不做分支，能复用的不新建。** 需求必须声明是否复用现有入口、页面、能力项配置，禁止默认新起一套。
5. **准入 = 承诺。** 需求方在准入单上签的是"上线后我会做哪些运营动作、用什么数据证明有效"，不是"我要这个功能"。

---

## 三、角色与权责

| 角色 | 职责 | 不承担 |
|------|------|--------|
| 需求方（运营） | 出方案书与设计、定指标与埋点、准备上线运营动作、上线后复盘 | 不把"想不清楚"的部分推给研发 |
| 负责人（守门人） | 判定准入/退回/降级、裁决优先级与资源冲突 | 不代需求方补方案 |
| UI / UE | 视觉与交互落地、输出设计稿与标注 | 不承担方案设计 |
| 研发 | 技术方案、排期、开发与自测 | 不猜测缺失的需求细节 |
| 测试 | 按验收标准执行、输出验收结论 | 不按"感觉"验收 |

## 四、需求分级与对应门槛

| 级别 | 定义 | 必要材料 | 审批人 | 时限 |
|------|------|----------|--------|------|
| **L0 线上故障** | 崩溃、不可用、资损、合规风险 | 故障单（现象 + 影响面 + 复现） | 负责人（可先修后补单） | 2 小时内响应 |
| **L1 小优化** | ≤3 人天、无新页面、不改数据模型 | 需求单（简版：定义 + 指标 + 验收） | 负责人 | 当日 |
| **L2 功能需求** | 新功能、改流程、新配置项 | **完整《需求方案书》** | 负责人（周会评审） | 每周一次 |
| **L3 大版本需求** | 跨模块、跨端（APP + 云端 + 固件）联动、影响多个页面 | **完整《需求方案书》+ 排期与资源承诺** | 负责人（立项会） | 每周一次 |

> 分级由提交人初判、负责人复核。**不允许把 L2 伪装成 L1 抢排期**——一旦发现，该需求直接降级并延后一个周期。

## 五、三项一票否决

以下任一项缺失，**当场退回，不进评审**：

| # | 否决项 | 判定标准 |
|---|--------|----------|
| 1 | **无验收标准** | 无法列出"做完后逐条可演示、可勾选"的验收清单 |
| 2 | **无埋点/数据方案** | 关键路径没有事件、没有公共参数、没有数据回收口径 |
| 3 | **无合规评估** | 未判定是否新增权限、是否需改隐私协议/用户协议、是否涉未成年人、是否涉数据出境与存储 |

补充：涉及**能力项配置**的需求，还必须写明两层语义——「APP 端展示项」与「下发固件默认值」；只写"加个配置"视为不完整。

## 六、运营侧准入：《需求方案书》标准

**提交物为一篇方案书（微文档），须包含以下 10 章，缺章即退回。**

### 6.1 一句话定义

格式固定：**给【哪类用户】，在【什么场景】下，解决【什么问题】，期望达到【什么结果】。**

- ✅ "给已完成配网但未添加设备的新用户，在首次打开首页时，解决找不到添加入口的问题，期望添加率提升 8 个点。"
- ❌ "首页加一个引导弹窗。"

### 6.2 背景与用户证据

至少提供一种证据：客服工单（条数/关键词）、用户访谈结论、后台数据异常点、竞品已上线截图。
**只有"我觉得"的需求，直接排最低优先级。**

### 6.3 用户场景与流程

- 入口 → 页面 → 出口，完整路径；
- 标注返回路径、异常分支、中断后如何恢复；
- 画出流程图（文字流程亦可，但节点必须齐全）。

### 6.4 页面设计（运营自出（稿图即可，描述齐全），UI 只做视觉）

运营必须交付到"研发看完能直接估算人天"的程度：

| 必含内容 | 具体要求 |
|----------|----------|
| 线框/原型 | 逐页给出，标注区域与控件类型（不是潦草截图） |
| **状态矩阵** | 空态 / 加载 / 失败 / 无权限 / 超长文本 / 无网络 —— 六态逐页确认 |
| 交互说明 | 点击、滑动、返回、多选、二次确认等行为描述 |
| 文案终稿 | 标题、按钮、提示、Toast、错误语；需多语言的标注语种 |
| 参考与禁区 | 参考页面截图 + 明确"不要做成什么样" |

> 未提供状态矩阵与文案终稿的方案，一律退回。这两项是开发期返工的最大来源。

### 6.5 指标四件套（缺一不可）

| 项 | 要求 | 示例 |
|----|------|------|
| 计算口径 | 分子/分母、数据来源表、统计维度 | 配网成功设备数 ÷ 发起配网设备数，取设备维表 |
| 现状基线 | 一个可信的当前值 | 78% |
| 预期值与窗口 | 目标值 + 观测周期 | 85%，上线后 T+14 天 |
| 判定方式 | 全量 / AB 实验（分流、样本、显著性） | AB 10% 分流，双侧 95% 置信 |

> **基线拿不出来的需求，先做数据埋点或调研，不要立项。** 只有目标值没有基线的，视为无指标。

### 6.6 埋点方案

- 关键路径的曝光 / 点击 / 转化 / 失败事件清单；
- 事件名、触发时机、属性字段；
- **按现有《埋点事件公共参数规范》补齐 13 项必选公共参数**；
- 与 6.5 的指标一一对应（哪个指标由哪几个事件算出）。

### 6.7 上线运营动作

需求上线 ≠ 效果产生。必须写明：

- 谁、在什么时间点、做什么（推送 / 活动 / 新人引导 / 客服话术 / 渠道素材 / 商家通知）；
- 需要的运营素材清单与交付时间（图片、文案、多语言）；
- 是否需要灰度与分批放量。

### 6.8 验收标准

逐条可勾选、可演示，例如：

1. 未配网用户在首页可见引导入口，点击进入配网流程；
2. 已完成配网用户不再看到该入口；
3. 无网络时展示指定错误文案，重试可恢复。

### 6.9 范围与不做清单

- **本次做什么**（MVP，不超过 5 条）；
- **本次明确不做什么**（并列写清，防止范围蔓延）；
- **复用声明**：是否复用现有入口 / 页面 / 组件 / 能力项配置；若新建，说明为什么不能复用。

### 6.10 资源、依赖与风险

- 依赖方（固件 / 云端 / 三方平台 / 支付）与对接人、对接时间；
- 上线窗口与不可用时段；
- 回滚方案与触发条件。

## 八、评审机制

- **频率**：每周固定一次，60 分钟；L0 随时插队但需补单。
- **形式**：答辩制。提出人 5 分钟回答三问——**给谁解决什么问题 / 怎么衡量成功 / 不做会怎样**；其余时间只做判定。
- **判定**：`准入` / `退回补材料` / `降级` / `不做（归档）`。会上不讨论方案细节，细节会后一对一。
- **留痕**：每次评审输出记录表（见附录 B），退回需写明缺哪项。

## 九、企业微信落地配置

| 环节 | 企业微信能力 | 配置要点 |
|------|--------------|----------|
| 收需求 | **收集表** | 按第七章字段建表，设为必填；提交后自动进表 |
| 需求池 | **多维表格** | 视图：待评审 / 已准入 / 开发中 / 待验收 / 已上线 / 已归档；按级别、负责人、日期分组 |
| 准入审批 | **审批** | L2/L3 走审批流：需求方 → 负责人；附带方案书链接 |
| 状态通知 | **群机器人** | 状态变更自动推送到「APP 需求群」，减少口头同步 |
| 材料沉淀 | **微文档** | 方案书、原型、埋点方案统一放微文档，禁止散落聊天记录 |
| 评审会 | **会议 + 群公告** | 会前 1 天由机器人推送本周待评审清单 |
| 复盘 | **多维表格看板** | T+7 / T+30 数据回填，未达标必填归因 |

> 原则：**所有需求只有一条入口（收集表）**。微信私聊、口头、临时会议提出的需求，一律回复"请提交收集表"。

## 十、状态机与流转时限

```
待提交 → 待评审 → 准入 → 排期 → 开发中 → 待验收 → 已上线 → 复盘 → 归档
                ↘ 退回补材料（限 5 个工作日内补齐，逾期自动归档）
```

| 状态 | 责任人 | 时限 |
|------|--------|------|
| 待评审 | 需求方 | 提交后 7 日内安排评审 |
| 退回补材料 | 需求方 | 5 个工作日内补齐 |
| 待验收 | 需求方 + 测试 | 提测后 3 个工作日内完成 |
| 已上线 → 复盘 | 需求方 | T+7 数据快报，T+30 正式复盘 |

---

## 十一、上线后效果回收

1. **T+7**：提交数据快报（是否达到阶段性预期，是否有异常）。
2. **T+30**：正式复盘，三选一结论——`达标` / `未达标（归因）` / `数据异常（重测）`。
3. 归因只能选三类：功能问题 / 运营未执行 / 口径或埋点错误。
4. **未按期复盘的需求，提出人下季度需求额度减半**；连续两次未复盘，暂停提交权限一个月。

---

## 十二、退回与申诉

- 退回意见必须写明"缺哪一章/哪一项"，禁止"再完善一下"这类模糊退回。
- 需求方补齐后可重新提交，记录中保留退回次数。
- 对判定有异议，可在群内 @ 负责人说明，由负责人当周裁决；**不接受在评审会外强行推进**。
