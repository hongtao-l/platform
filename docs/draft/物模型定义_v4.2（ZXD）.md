# 平台物模型定义
- 全面实行平台定义设备、平台定义应用和平台定义业务，解决不同厂商之间设备兼容性问题，设备在不同APP之间兼容性问题，解决业务一致性问题。
- 同时通过物模型自定义项，实现不同厂商设备差异性问题，不同应用开发者业务差异性问题。
- 实现一套既有规则，又开放包容的物模型定义方案。

### 1.1 图像采集相关能力项设计
- 定义图像采集相关属性能力，包括镜头参数、采集参数、编码参数、PTZ参数以及通用的能力参数
#### 1.1.1 采集码流属性定义能力项  -- 能力项ID："CaptureStreamProperty"
- 定义采集码流的属性
 {
    "capture_stream_count":1, //采集码流数量
    “capture_stream_param”:[
        {
            "capture_stream_id":0, //采集码流ID，从0开始编号
            "conbine_stream_type":0, //合成流类型，0:非合并流；1.双镜头单流（左右合并）2.双镜头单流（上下合并）；3.三镜头单流（上下三路合并）；4.三镜头单流（上2路下1路合并）；5.三镜头单流（上1路下2路合并）；6.三镜头单流（左右三路合并）7.四镜头单流（上下合并）；8.四镜头单流（上2下2合并）
            "conbine_lens_ids":[] //合并镜头ID列表，若conbine_stream_type为0，则没有该项，lens_id从0开始编号；
            "flip_type":0, //采集流翻转类型，0:不翻转；1.水平翻转；2.垂直翻转；3.水平垂直翻转（倒装）
            "focal_type":0, //焦距类型：0.固定焦距；1.机械变焦；2.电子变焦（设备侧）；3.电子变焦（APP侧）
            "focal_length":10, //当前图像焦距长度
            "focal_length_min":1, //图像焦距支持的最小值
            "focal_length_max":28, //图像焦距支持的最大值
            "encode_stream_count":1, //采集码流对应的编码码流数量
        }
    ]
 }

#### 1.1.2 编码码流属性定义能力项 -- 能力项ID："EncodeStreamProperty"
- 定义编码码流的属性
- 视频编码参数（宽/高/编码类型/帧率/码率）由 1.1.19 `video_param` 统一承载，本能力项仅保留编码码流标识与编码模式。

    "video_encode_mode":0,//视频编码模式，0:CBR,1:VBR,2:AVBR
 }

            "correct_algorithm_id":"",//算法ID标记，不同厂商不同矫正算法标记不一致

#### 1.1.4 P/T属性定义能力项 -- 能力项ID："PTProperty"
- 定义P/T的属性，Z的能力已经在StreamProperty中定义，这里只定义P/T的属性
- 该能力项为 PTZ 各能力的开关/能力声明（能力位），具体坐标/预置位/巡航等数据由 1.1.5～1.1.13 各自能力项承载。
 {
    "pt_control_type":0, //P/T控制类型，0:不支持；1.支持设备控制；2.支持分镜头控制；
    "pt_ability":[1,2,3],//不支持：则无此项；支持设备控制：数组只有1个值；支持分镜头控制：几个镜头就几个值；取值：0.不支持P/T；1.支持P；2.支持T；3.支持P&T
    "ptz_3d_position_ability":0,// PTZ 3D居中能力：0.不支持；1.支持；设备有坐标系；
    "ptz_preset_ability":0, // PTZ预置位设置能力，0.不支持；1.支持； 多个镜头有多个PTZ的一并控制，归属设备能力；
    "ptz_cruise_ability":0, // PTZ巡航能力，0.不支持；1.支持; 多个镜头有多个PTZ的一并控制，归属设备能力；
 }
- 注：速度能力不在本能力项声明，由 1.1.5 `speed_range`（固件上报 min/max，默认 0～52）承载；各服务的 `speed` 统一取值 0～`speed_range.max`，不再使用原 `ptz_speed`（1～5 等级）定义。

#### 1.1.5 PTZ 坐标属性 -- 能力项ID："PTZCoordinateProperty"
- 定义 PTZ 坐标系能力属性，**只读**（`bWritable=FALSE`）；步长总数、速度范围由固件上报，当前逻辑坐标由 SDK 维护并随属性/事件上报。
- 对外统一使用「逻辑坐标」0～100，中心 X=50、Y=50、Z=50；固件层只处理物理步长，SDK 依据各轴步长总数完成逻辑坐标↔物理步长换算（step = coord * count / 100）。
- 平台下发 `get_property_capability` 时，SDK 上报：
 {
    "coordinate":{ //当前逻辑坐标，0～100
        "x":50, //水平逻辑坐标，中心50
        "y":50, //垂直逻辑坐标，中心50
        "z":50  //变焦逻辑坐标，无变焦固定50
    },
    "step_range":{ //各轴物理步长总数（固件上报，SDK 换算用）
        "x":4096, //水平轴步长总数
        "y":1536, //垂直轴步长总数
        "z":0      //变焦轴步长总数，0 表示无变焦
    },
    "speed_range":{ //速度范围（固件上报，SDK 转动时校验）
        "min":0,  //最小速度
        "max":52  //最大速度
    }
 }
- 原 `PTZPositionProperty`（`lens_id/pt_position_list`）已不再由设备侧实现；预置位改由 `PTZPresetManageService` 管理（见 1.1.8）。

#### 1.1.6 PTZ 移动到坐标/预置位 -- 能力项ID："PTZGotoPositionService"
- 定义移动到逻辑坐标或调用预置位的业务，两者互斥，二选一。
 {
    "preset_id":1, //预置位编号，携带时按预置位调用（与 x/y 二选一）
    "x":80,        //目标水平逻辑坐标，0～100（按坐标移动时与 y 必填）
    "y":30,        //目标垂直逻辑坐标，0～100（按坐标移动时与 x 必填）
    "speed":40     //速度，可选；取值 0～speed_range.max（默认 0～52），缺省取 speed_range.max
 }

#### 1.1.7 PTZ 转动控制 -- 能力项ID："PTZControlService"
- 定义手动方向/变焦转动与停止业务。
 {
    "direction":"up", //转动方向，字符串：stop/up/down/left/right/zoom_in/zoom_out/left_up/left_down/right_up/right_down
    "speed":30,       //速度，可选；取值 0～speed_range.max（默认 0～52），缺省取 speed_range.max
    "steps_x":0,      //水平步长，可选；纯水平/斜向转动时非0
    "steps_y":100     //垂直步长，可选；纯垂直/斜向转动时非0
 }
- `direction=stop` 时忽略 `speed/steps_x/steps_y`，直接下发停止指令。
- 原 `lens_id/ptz_control_type/pt_position_id/ptz_type/ptz_step` 已不再使用；移动到预置位/坐标走 `PTZGotoPositionService`（见 1.1.6）。

#### 1.1.8 PTZ 预置位管理 -- 能力项ID："PTZPresetManageService"
- 定义预置位的增/删/查/调用业务。
 {
    "op":"add",   //操作类型：add/del/goto/query
    "preset_id":1,//预置位编号（1~16）
    "name":"门口",//预置位名称，add 时有效
    "x":80,       //预置位水平逻辑坐标，add 时有效
    "y":30,       //预置位垂直逻辑坐标，add 时有效
    "speed":40    //速度，可选，goto 时有效；取值 0～speed_range.max（默认 0～52），缺省取 speed_range.max
 }
- `op` 取值语义：`add` 保存坐标（满则返回 `32606`）；`del` 删除（不存在返回 `32605`）；`goto` 调用（不存在返回 `32605`）；`query` 查询坐标并经回执 `output` 返回。

#### 1.1.9 PTZ 看守位管理 -- 能力项ID："PTZGuardManageService"
- 定义空闲后自动返回指定预置位的看守业务。
 {
    "op":"set",      //操作类型：set/cancel
    "preset_id":1,   //看守预置位编号，set 时必填
    "return_delay":60 //空闲返回延时，单位秒，0=立即返回
 }
- 原 `GuardPositionProperty`、`return_interval` 已不再由设备侧实现。

#### 1.1.10 PTZ 巡航位管理 -- 能力项ID："PTZPatrolManageService"
- 定义按预置位序列循环转动的巡航路线管理业务。
 {
    "op":"set",       //操作类型：set/start/stop
    "patrol_id":1,    //巡航路线编号（1~4），set/start 时必填
    "points":[1,2,3], //途经预置位编号数组（1~16 个），set 时必填
    "dwell_time":10   //每点停留秒数，set 时必填
 }
- 原 `CruiseProperty` / `cruise_control` / `pt_position_list` / `stay_interval` 已不再由设备侧实现。

#### 1.1.11 PTZ 坐标系重置 -- 能力项ID："PTZResetService"

#### 1.1.14 图片采集通用功能属性能力项设计 -- 能力项ID："ImageCommonProperty"

### 1.11 录像记录模块相关能力项设计
- v5 将录像拆为 **8 个可写能力项**：4 个属性（`LocalRecordProperty` / `LocalPictureProperty` / `CloudRecordProperty` / `CloudPictureProperty`）+ 4 类策略（本地/云 × 定时/事件）；另保留 `RecordStatusProperty`（状态定义）与录像/抓图服务。
- **属性**记录“录什么、存多久、默认参数”：本地录像与本地抓图拆为两个属性，云录像与云图片拆为两个属性；各自携带码流/格式/保留天数，互不覆盖。
- **策略**记录“什么时候录、什么事件触发、动作参数”：时间条件、事件条件、预录/时长/延时/间隔；策略不重复携带码流，码流只在属性中定义。
- **本地与云分治**：本地属性/策略只影响卡录像，云属性/策略只影响云存；平台可分别查询、分别下发，互不覆盖。
- **抓图服务**：`RecordSnapshotService` 定义抓图格式、张数与间隔，支持一次下发多张抓图；云图片格式含私有格式，满足 S3 私密存储。

#### 1.11.1 本地录像能力项 -- 能力项ID："LocalRecordProperty"

- 定义本地（SD 卡）录像的**录制码流、录像类型、事件录像默认参数、本地录像存储策略**；不包含本地抓图（由 `LocalPictureProperty` 独立承载），也不包含定时计划或事件条件（分别由 `LocalScheduleRecordPolicy`、`LocalEventRecordPolicy` 承载）。
- 手动录像、平台即时录像由 `RecordManualService` / `RecordPlatformService` 触发，不在本属性中记录。
- 属性值示例：

```json
{
    "record_stream_count": 2,
    "record_stream_list": [
        { "capture_stream_id": 0, "encode_stream_id": 0 },
        { "capture_stream_id": 0, "encode_stream_id": 1 }
    ],
    "record_switch": { "0": 1 },
    "record_type": 3,
    "event_record_sec": 15,
    "pre_record_sec": 5,
    "lifecycle": {
        "video_days": 30,
        "event_days": 30,
        "overwrite_enable": 1,
        "space_watermark": 5
    }
}
```

- 字段说明：

| 字段 | 类型 | 取值/范围 | 必填 | 说明 |
| --- | --- | --- | --- | --- |
| `record_stream_count` | int | `0～8` | 否 | 录制码流数量；与 `record_stream_list` 长度必须一致，不一致整包拒绝 |
| `record_stream_list` | array | — | 条件必填 | 录制码流列表，每项为 `(capture_stream_id, encode_stream_id)` 二元组；同一二元组不可重复 |
| `record_stream_list[].capture_stream_id` | int | `0～7` | 是 | 采集码流 ID，从 0 开始 |
| `record_stream_list[].encode_stream_id` | int | `0～7` | 是 | 该采集码流下的编码码流 ID，从 0 开始；同一采集流可列多个编码流 |
| `record_switch` | object | key=采集流 ID，value=`0/1` | 否 | 手动录像开关，按采集流维度；作用于该采集流在 `record_stream_list` 中列出的全部编码流 |
| `record_type` | int | `0/1/2/3` | 是 | `0` 关闭自动录像；`1` 仅事件；`2` 定时/全天；`3` 事件+定时（按位或） |
| `event_record_sec` | int | `0～3600`，默认 `15` | 否 | 事件录像默认时长（秒），从事件触发时刻起算；`0` 表示持续到事件结束；事件策略动作可覆盖 |
| `pre_record_sec` | int | `0～60`，默认 `0` | 否 | 事件预录默认秒数；事件策略动作可覆盖 |
| `lifecycle.video_days` | int | `0～3650` | 否 | 本地视频保留天数；`0` 表示关闭按天老化 |
| `lifecycle.event_days` | int | `0～3650` | 否 | 本地事件记录保留天数；`0` 表示关闭按天老化 |
| `lifecycle.overwrite_enable` | int | `0/1`，默认 `1` | 否 | `0` 空间耗尽后停止录像并上报空间不足；`1` 按最旧数据循环覆盖 |
| `lifecycle.space_watermark` | int | `0～90`，默认 `5` | 否 | **剩余空间水位百分比**：剩余空间低于该值时清理最旧数据；`0` 表示关闭水位清理 |

- 行为说明：
  1. `record_type=0` 时本地不启动任何录像（含 `RecordManualService` / `RecordPlatformService`）；服务只更新状态，不落盘。
  2. `record_type=1` 时只允许 `LocalEventRecordPolicy` 生效，定时策略忽略。
  3. `record_type=2` 时只允许 `LocalScheduleRecordPolicy` 生效；没有任何启用的定时策略时按 **24 小时连续录像** 处理。
  4. `record_type=3` 时两类策略都生效：定时时段内连续录像，事件命中时按事件参数叠加，只录一份数据。
  5. `event_record_sec` 是默认值；事件策略 `record_duration` 非 0 时以策略为准，两者都为 0 时持续到事件结束。
  6. 多编码同时录制由设备能力决定；不支持时返回明确错误，不回退为只录第一路。

#### 1.11.2 本地抓图能力项 -- 能力项ID："LocalPictureProperty"

- 独立管理本地（SD 卡）抓图的开关、存储格式、定时抓图周期与保留天数；与 `LocalRecordProperty` 分开下发、分开回读，互不覆盖。
- 事件联动抓图、定时抓图、手动/服务抓图共用本属性的存储格式；是否自动抓图由 `picture_enable` 控制。
- 属性值示例：

```json
{
    "picture_enable": 1,
    "picture_days": 7,
    "picture_format": "jpeg",
    "timing_period_sec": 300
}
```

- 字段说明：

| 字段 | 类型 | 取值/范围 | 必填 | 说明 |
| --- | --- | --- | --- | --- |
| `picture_enable` | int | `0/1`，默认 `0` | 是 | 本地自动抓图开关；`0` 停止定时抓图与事件联动抓图，不影响 `RecordSnapshotService` 显式抓图 |
| `picture_days` | int | `0～3650` | 否 | 本地图片保留天数；`0` 表示关闭按天老化 |
| `picture_format` | string | `jpeg` / `hmp`，默认 `jpeg` | 否 | 本地抓图存储格式；`jpeg` 为单张文件，`hmp` 为聚合文件 |
| `timing_period_sec` | int | `0～86400`，默认 `0` | 否 | 定时抓图周期（秒），`0` 表示关闭；不属于录像计划 |

- 行为说明：
  1. `picture_days` 从 `LocalRecordProperty.lifecycle` 移出，本地图片老化只由本属性决定。
  2. `picture_format` 对定时、事件、手动/服务抓图统一生效；单次服务可用 `RecordSnapshotService.picture_format` 覆盖。
  3. `picture_enable=0` 时定时抓图与事件联动抓图不执行；显式 `RecordSnapshotService` 抓图仍可执行并落盘。
  4. 本属性不改变 `LocalRecordProperty.record_type`，抓图开关与录像开关相互独立。
  5. 全量同步本属性只重置本属性字段，不清空本地录像码流、策略或 `record_switch`。

#### 1.11.3 云录像能力项 -- 能力项ID："CloudRecordProperty"

- 定义云存的**录制码流、录像类型、云存储时长、事件录像默认参数**；不包含云定时/云事件策略，也不包含套餐明细与单段时长。
- 云存时长唯一来源为 `storage_days`；云图片由独立能力项 `CloudPictureProperty` 承载。
- 属性值示例：

```json
{
    "record_stream_count": 1,
    "record_stream_list": [
        { "capture_stream_id": 0, "encode_stream_id": 0 }
    ],
    "record_type": 1,
    "storage_days": 30,
    "event_record_sec": 15
}
```

- 字段说明：

| 字段 | 类型 | 取值/范围 | 必填 | 说明 |
| --- | --- | --- | --- | --- |
| `record_stream_count` | int | `0～8` | 否 | 云存录制码流数量；与 `record_stream_list` 长度必须一致 |
| `record_stream_list` | array | — | 条件必填 | 云存录制码流列表，语义同 1.11.1 |
| `record_type` | int | `0/1/2` | 是 | `0` 不支持/未订阅；`1` 事件云存；`2` 全天/计划云存；云侧不定义 `3` |
| `storage_days` | int | `0～3650` | 是 | 云存储时长（天），云存时长唯一来源；`0` 表示无云存，云策略不生效 |
| `event_record_sec` | int | `0～3600`，默认 `15` | 否 | 事件云存默认时长（秒），从事件触发时刻起算；`0` 表示持续到事件结束；事件策略动作可覆盖 |

- 行为说明：
  1. `record_type=0` 或 `storage_days=0`：不启动云上传，云策略一律忽略。
  2. `record_type=1`：只允许 `CloudEventRecordPolicy` 生效，云定时策略忽略。
  3. `record_type=2`：只允许 `CloudScheduleRecordPolicy` 生效；没有启用的云定时策略时按 **24 小时连续云存** 处理。
  4. 云 `record_type` 是单一订阅类型，事件档与全天档互斥；如后续需要表达组合，另设 `record_type_mask`，不复用本字段。
  5. 平台负责云存订阅有效性；订阅失效时下发 `record_type=0` 或 `storage_days=0`，设备不基于本地时间判断过期。

#### 1.11.4 录像状态能力项 -- 能力项ID："RecordStatusProperty"

- 定义录像状态能力项：

```json
{
    "local_record_status": 0,
    "record_error_code": 0,
    "cloud_record_status": 0,
    "cloud_record_error_code": 0
}
```

| 字段 | 取值 | 说明 |
| --- | --- | --- |
| `local_record_status` | `0/1/2/3` | 本地录像状态：0 未录像；1 录像中；2 录像完成；3 录像失败 |
| `record_error_code` | int | 本地错误码：0 无错误；1 录像失败；2 SD 卡存储错误；3 SD 卡空间不足 |
| `cloud_record_status` | `0/1/2/3` | 云录像状态：0 未录像；1 录像中；2 录像完成；3 录像失败 |
| `cloud_record_error_code` | int | 云错误码：0 无错误；1 录像失败；2 云存储连接超时；3 云存储存储超时；4 云存储鉴权失败 |

> 设备侧当前未注册该属性，录像状态经事件/属性回执上报；本节保留平台定义。

#### 1.11.5 录像能力业务能力项 -- 能力项ID："RecordService"

- 定义录像开关切换业务，录像参数优先级为：手动 > 事件 > 定时。
- 设备侧 v5 将本服务拆为三个可写 Service：`RecordManualService`、`RecordPlatformService`、`RecordSnapshotService`；下表为 `RecordService` 的统一语义。

```json
{
    "record_mode": 1,
    "record_streamid": 0,
    "record_data_format": 1,
    "record_data_interval": 1000,
    "pre_record_time": 2,
    "record_duration": 15
}
```

| 字段 | 取值 | 说明 |
| --- | --- | --- |
| `record_mode` | `1/2/4` | 录像模式位掩码：1 计划；2 事件；4 手动 |
| `record_streamid` | int | 手动录像码流，主/次/中码流 |
| `record_data_format` | `1～5` | 1 码流；2 I 帧；3 JPEG；4 GIF；5 私有格式 |
| `record_data_interval` | int | 数据间隔，仅 I 帧/JPEG 有效，单位毫秒 |
| `pre_record_time` | int | 预录时长，单位秒 |
| `record_duration` | int | 录像时长，单位秒 |

#### 1.11.6 定时录像策略定义 -- 能力项ID："LocalScheduleRecordPolicy" / "CloudScheduleRecordPolicy"

- 名称与职责：

| 能力项 ID | 作用域 | 职责 |
| --- | --- | --- |
| `LocalScheduleRecordPolicy` | 本地卡录像 | 定义本地定时录像的时间条件与动作参数 |
| `CloudScheduleRecordPolicy` | 云存 | 定义云定时上传的时间条件与动作参数 |

- 策略只描述“什么时间录/传”，不重复携带录制码流；码流由 1.11.1/1.11.3 的属性决定。
- 本地与云统一按《01.统一命名》策略定义模板下发：`policy_id` / `policy_type` 为字符串，时间条件使用 `policy_schedule.schedule_list[]`，动作使用 `policy_services[]`。两类能力项字段结构一致，仅作用域与动作落点不同。
- 示例（本地/云结构相同，仅能力项 ID 不同）：

```json
{
    "policy_count": 1,
    "policy_list": [
        {
            "policy_id": "sched-1",
            "policy_type": "schedule",
            "policy_name": "工作日与周末夜间定时",
            "policy_enable": 1,
            "policy_priority": 5,
            "policy_schedule": {
                "schedule_count": 2,
                "schedule_list": [
                    {
                        "schedule_id": 1,
                        "schedule_name": "工作日夜间",
                        "schedule_type": 1,
                        "schedule_enable": 1,
                        "schedule_weekday": 31,
                        "schedule_starttime": 0,
                        "schedule_endtime": 28800
                    },
                    {
                        "schedule_id": 2,
                        "schedule_name": "周末夜间",
                        "schedule_type": 1,
                        "schedule_enable": 1,
                        "schedule_weekday": 96,
                        "schedule_starttime": 0,
                        "schedule_endtime": 28800
                    }
                ]
            },
            "policy_condition": {
                "logic": 1,
                "events": []
            },
            "policy_services": [
                {
                    "service_id": "RecordService",
                    "service_param": {
                        "record": 1,
                        "pre_record_sec": 0,
                        "record_duration": 0,
                        "post_record_sec": 0,
                        "record_interval": 0
                    }
                }
            ]
        }
    ]
}
```

- 字段说明（本地/云通用）：

> 下表“必填”以新模板为准；旧 v5 扁平缓存允许缺省，由设备补默认值或按能力项推断，兼容规则见 1.11.11。

| 字段 | 类型 | 取值/范围 | 必填 | 说明 |
| --- | --- | --- | --- | --- |
| `policy_count` | int | `0～8` | 否 | 策略数量；与 `policy_list` 长度必须一致 |
| `policy_list` | array | — | 是 | 策略列表；全量同步时整体替换，空列表清空该类型全部策略 |
| `policy_id` | string | 非空字符串，最大 31 字节，能力项内唯一 | 是 | 策略编号，按平台编号字符串下发；缺省时设备按列表序号补默认值 |
| `policy_type` | string | `"schedule"` | 是 | 定时策略固定为 `"schedule"`，必须与能力项匹配 |
| `policy_name` | string | 最大 32 字节 | 否 | 策略名称 |
| `policy_enable` | int | `0/1` | 是 | `0` 禁用；`1` 使用 |
| `policy_priority` | int | `1～10` | 是 | 数值越小优先级越高 |
| `policy_schedule` | object | — | 是 | 时间条件 |
| `policy_schedule.schedule_count` | int | `1～8` | 是 | 时间段数量；与 `schedule_list` 长度必须一致 |
| `policy_schedule.schedule_list` | array | — | 是 | 时间段列表 |
| `policy_schedule.schedule_list[].schedule_id` | int | `1～N` | 是 | 时间段 ID，同一策略内唯一 |
| `policy_schedule.schedule_list[].schedule_name` | string | 最大 32 字节 | 否 | 时间段名称 |
| `policy_schedule.schedule_list[].schedule_type` | int | `0/1/2` | 否 | `0` 单次；`1` 循环；`2` 永久；录像建议 `1` |
| `policy_schedule.schedule_list[].schedule_enable` | int | `0/1` | 是 | 时间段是否启用 |
| `policy_schedule.schedule_list[].schedule_weekday` | int | `1～127` | 是 | 7 位掩码，bit0=周一 … bit6=周日；`127` 表示每天 |
| `policy_schedule.schedule_list[].schedule_starttime` | int | `0～86399` | 是 | 开始时间，UTC 当天秒数 |
| `policy_schedule.schedule_list[].schedule_endtime` | int | `0～86400` | 是 | 结束时间，UTC 当天秒数；不得与开始时间相同；大于开始时间表示同日时段，小于开始时间表示跨零点 |
| `policy_condition` | object | — | 否 | 定时策略不使用；如模板携带，设备忽略 |
| `policy_services` | array | 至少 1 项 | 是 | 策略动作列表 |
| `policy_services[].service_id` | string | `"RecordService"` | 是 | 录像动作能力项 ID |
| `policy_services[].service_param` | object | — | 是 | 该 Service 的参数 |
| `policy_services[].service_param.record` | int | `0/1` | 否 | `0` 保留策略但不启动录像；`1` 启动 |
| `policy_services[].service_param.pre_record_sec` | int | `0～60` | 否 | 预录秒数；覆盖属性默认值 |
| `policy_services[].service_param.record_duration` | int | `0` | 否 | 定时策略固定为 `0`，表示持续到时段结束 |
| `policy_services[].service_param.post_record_sec` | int | `0` | 否 | 定时策略不使用，固定 `0` |
| `policy_services[].service_param.record_interval` | int | `0～86400` | 否 | 两次录像最小间隔（秒）；`0` 表示不限制 |

- `schedule_type` 由平台定义并随策略保存；设备侧录像触发统一按 `schedule_weekday` + `schedule_starttime` / `schedule_endtime` 判断时段，`0` 单次 / `2` 永久的日期语义由平台侧约束。
- 跨零点时段（`schedule_starttime > schedule_endtime`）零点后的部分仍按开始日期的 `schedule_weekday` 判断；例如周一 22:00～周二 02:00 只填周一。
- 录像策略当前仅消费一个 `RecordService` 动作；同一策略内出现多个 `RecordService` 视为非法。

- 生效规则：
  1. **门控**：本地仅当 `record_type` 为 `2/3` 时生效；云仅当 `record_type=2` 且 `storage_days>0` 时生效。
  2. **并集**：同一能力项内所有 `policy_enable=1` 的策略、同一策略内所有 `schedule_enable=1` 的时间段取并集，任一命中即触发。
  3. **冲突裁决**：多个策略同时命中且动作参数不同，取 `policy_priority` 最小者；同优先级按 `policy_id` 的数值升序；非数字编号按列表顺序。
  4. **无策略**：门控通过且没有启用的定时策略时，按 24 小时连续录像/云存处理。
  5. **全量同步**：`policy_list` 整体替换；缺省该能力项时保留缓存；空列表表示关闭该类型全部策略。
  6. **时段**：一条策略可包含多个时间段；`schedule_starttime > schedule_endtime` 表示跨零点，`schedule_starttime == schedule_endtime` 非法。
  7. **叠加**：定时与事件可同时命中，只录一份数据，录像模式按位叠加；动作参数按“手动 > 事件 > 定时”取值。

#### 1.11.7 事件录像策略定义 -- 能力项ID："LocalEventRecordPolicy" / "CloudEventRecordPolicy"

- 名称与职责：

| 能力项 ID | 作用域 | 职责 |
| --- | --- | --- |
| `LocalEventRecordPolicy` | 本地卡录像 | 定义本地事件触发条件与录像动作 |
| `CloudEventRecordPolicy` | 云存 | 定义云事件触发条件与上传动作 |

- 本地与云统一按《01.统一命名》策略定义模板下发：事件条件使用 `policy_condition.logic` + `policy_condition.events[]`，动作使用 `policy_services[]`。两类能力项字段结构一致，仅作用域与动作落点不同。
- 示例（本地/云结构相同，仅能力项 ID 不同）：

```json
{
    "policy_count": 1,
    "policy_list": [
        {
            "policy_id": "event-1",
            "policy_type": "event",
            "policy_name": "移动侦测/人形事件录像",
            "policy_enable": 1,
            "policy_priority": 5,
            "policy_schedule": {},
            "policy_condition": {
                "logic": 2,
                "events": [
                    "motion",
                    "person"
                ]
            },
            "policy_services": [
                {
                    "service_id": "RecordService",
                    "service_param": {
                        "record": 1,
                        "pre_record_sec": 5,
                        "record_duration": 15,
                        "post_record_sec": 0,
                        "record_interval": 0
                    }
                }
            ]
        }
    ]
}
```

- 字段说明（本地/云通用）：

> 下表“必填”以新模板为准；旧 v5 扁平缓存允许缺省，由设备补默认值或按能力项推断，兼容规则见 1.11.11。

| 字段 | 类型 | 取值/范围 | 必填 | 说明 |
| --- | --- | --- | --- | --- |
| `policy_count` | int | `0～8` | 否 | 策略数量；与 `policy_list` 长度必须一致 |
| `policy_list` | array | — | 是 | 策略列表；全量同步时整体替换，空列表清空该类型全部策略 |
| `policy_id` | string | 非空字符串，最大 31 字节，能力项内唯一 | 是 | 策略编号；缺省时设备按列表序号补默认值 |
| `policy_type` | string | `"event"` | 是 | 事件策略固定为 `"event"`，必须与能力项匹配 |
| `policy_name` | string | 最大 32 字节 | 否 | 策略名称 |
| `policy_enable` | int | `0/1` | 是 | `0` 禁用；`1` 使用 |
| `policy_priority` | int | `1～10` | 是 | 数值越小优先级越高 |
| `policy_condition` | object | — | 是 | 事件条件 |
| `policy_condition.logic` | int | `0/1/2` | 是 | `0` NOT；`1` AND；`2` OR |
| `policy_condition.events` | array | `1～4` 个 `event_id` | 是 | 平台事件定义清单中的事件 ID，单个 ID 最大 47 字节，同一策略内不重复 |
| `policy_schedule` | object | — | 否 | 事件策略不使用；如模板携带，设备忽略 |
| `policy_services` | array | 至少 1 项 | 是 | 策略动作列表 |
| `policy_services[].service_id` | string | `"RecordService"` | 是 | 录像动作能力项 ID |
| `policy_services[].service_param` | object | — | 是 | 该 Service 的参数 |
| `policy_services[].service_param.record` | int | `0/1` | 否 | `0` 保留策略但不启动录像；`1` 启动 |
| `policy_services[].service_param.pre_record_sec` | int | `0～60` | 否 | 预录秒数；覆盖属性默认值 |
| `policy_services[].service_param.record_duration` | int | `0～3600` | 否 | 事件录像时长；`0` 表示跟随事件结束或回退到属性 `event_record_sec` |
| `policy_services[].service_param.post_record_sec` | int | `0～3600` | 否 | 事件结束后延时停录秒数；仅当策略 `record_duration=0` 且未使用属性 `event_record_sec` 时生效 |
| `policy_services[].service_param.record_interval` | int | `0～86400` | 否 | 两次录像最小间隔（秒）；`0` 表示不限制 |

- 本地与云事件条件均不再使用 `event_type_mask` / `event_type`；`events[]` 中的 `event_id` 是策略唯一事件条件来源。设备为兼容旧 v5 缓存仍可读取旧字段，但新下发与持久化统一写模板结构。
- 策略动作参数统一从 `policy_services[].service_param` 读取；录像策略当前仅消费一个 `RecordService` 动作，多个 `RecordService` 视为非法。
- `logic=1` 且包含多个事件时，设备按 5 秒窗口合并同一策略的事件；`logic=0` 表示否定条件，设备不将其单独作为录像触发，需平台组合或拆分为正向事件策略。

- 生效规则：
  1. **门控**：本地仅当 `record_type` 为 `1/3` 时生效；云仅当 `record_type=1` 且 `storage_days>0` 时生效。
  2. **条件匹配**：按 `policy_condition.logic` 对 `events[]` 求值；`1` 表示所列事件全部发生，`2` 表示任一事件发生；`0` 为否定条件，不单独触发录像（见上文）。设备事件通知携带 `event_id` 时按字符串匹配，旧事件类型通知仍按数字事件类型兼容。
  3. **多策略命中**：所有命中事件都触发；动作参数取 `policy_priority` 最小者，同优先级取 `policy_id` 的数值最小者（非数字编号按列表顺序）；同一路流只录一份。
  4. **时长裁决**：策略 `record_duration > 0` > 属性 `event_record_sec > 0` > 持续到事件结束。
  5. **预录裁决**：策略 `pre_record_sec` > 属性 `pre_record_sec`。
  6. **叠加**：事件与定时同时命中时只录一份，模式按位叠加；动作参数按“手动 > 事件 > 定时”取值。
  7. **联动抓图**：设备侧事件策略命中后可联动抓图；抓图参数见 1.11.9。

#### 1.11.8 云图片能力项 -- 能力项ID："CloudPictureProperty"

- 独立表达云图片存取的开关、保留时长与云端图片格式，不与云视频 `CloudRecordProperty` 混用。
- 属性值示例：

```json
{
    "picture_enable": 1,
    "storage_days": 7,
    "picture_format": "private"
}
```

- 字段说明：

| 字段 | 类型 | 取值/范围 | 必填 | 说明 |
| --- | --- | --- | --- | --- |
| `picture_enable` | int | `0/1` | 是 | 云图片总开关；`0` 时设备不上传事件/手动抓图 |
| `storage_days` | int | `0～3650` | 是 | 云图片保留天数；`0` 等价关闭，云图片策略不生效 |
| `picture_format` | string | `jpeg` / `private`，默认 `jpeg` | 否 | 云端图片格式；`private` 为设备私有格式，原样上传、不注入 EXIF，配合 S3 私有桶/私有对象使用 |

- 行为说明：
  1. `picture_enable=0` 或 `storage_days=0`：事件/手动/服务抓图只落本地，不触发云图片上传。
  2. 云图片上传不依赖 `CloudRecordProperty.record_type`，视频云存与图片云存可独立订阅。
  3. 云图片存储天数只作为上传维度参数；平台侧订阅有效性由平台下发值表达。
  4. `picture_format` 只影响云端对象格式，不改变本地 `LocalPictureProperty.picture_format`；`private` 时设备跳过 JPEG EXIF 注入，按私有文件原样上传。
  5. `private` 的私密性由 S3 私有桶/私有对象与访问凭据保证，不依赖文件名或内容混淆。
  6. 云图片按单张文件上传，要求本地落盘为 JPEG；HMP 为本地聚合文件，不直接上传，设备跳过该张云上传（本地 HMP 仍保留）。

#### 1.11.9 抓图服务能力项 -- 能力项ID："RecordSnapshotService"

- 定义显式抓图服务，支持指定格式、张数与多张之间的间隔；可一次下发抓取多张图片。
- 与 1.1.17 `SnapPictureService` 的关系：1.1.17 为平台通用抓图语义（毫秒间隔、镜头/全图/尺寸类型）；录像场景以本节 `RecordSnapshotService` 为准，间隔单位为毫秒，不包含镜头/尺寸类型，两者不叠加。
- 服务入参示例：

```json
{
    "nvr_channel_num": 0,
    "snap_type": 1,
    "picture_format": "jpeg",
    "picture_count": 3,
    "picture_interval": 500
}
```

- 字段说明：

| 字段 | 类型 | 取值/范围 | 必填 | 说明 |
| --- | --- | --- | --- | --- |
| `nvr_channel_num` | int | `0～7` | 是 | 路号，映射到采集流；缺省 `0` |
| `snap_type` | int | `1/2/3/4`，默认 `1` | 否 | 1 手动；2 定时；3 事件；4 巡检（设备按手动处理） |
| `picture_format` | string | `jpeg` / `hmp` | 否 | 本地落盘格式；缺省时使用 `LocalPictureProperty.picture_format` |
| `picture_count` | int | `1～10`，默认 `1` | 否 | 本次抓图张数；多张按顺序抓取并逐张落盘 |
| `picture_interval` | int | `0～60000`，默认 `0` | 否 | 多张之间的间隔（毫秒）；连续抓拍时按该间隔触发下一张，`picture_count=1` 时忽略 |

- 行为说明：
  1. 服务异步受理，不阻塞下行回执；多张抓图在设备侧按 `picture_interval`（毫秒）顺序执行，每张完成独立落盘、独立索引。
  2. `picture_format` 只覆盖本次本地落盘格式；云端图片格式仍由 `CloudPictureProperty.picture_format` 决定。
  3. `CloudPictureProperty.picture_enable=1` 且 `storage_days>0` 时，本次抓取的 JPEG 单图按云图片格式上传；`picture_format="hmp"` 只落本地聚合文件，不上传云端。
  4. `picture_count` 超过 `10`、`picture_interval` 超过 `60000`、格式不在枚举内时整包拒绝，不执行部分抓图。
  5. 服务不依赖 `LocalPictureProperty.picture_enable`；该开关只控制定时/事件自动抓图。

#### 1.11.10 能力项协同与生效规则

- 职责边界：

| 内容 | 属性 | 策略 | 服务 |
| --- | --- | --- | --- |
| 录制码流 `(cap, enc)` | 唯一定义 | 不重复定义 | 手动/平台服务可引用 |
| `record_type`、保留天数、覆盖/水位 | 定义 | 只受门控 | 不定义 |
| 事件默认时长、预录秒数 | 定义默认值 | 可覆盖 | 不定义 |
| 定时时段、事件条件 | 不定义 | 定义 | 不定义 |
| 抓图开关、格式、保留天数 | 对应图片属性定义 | 不定义 | 抓图服务可单次覆盖本地格式 |
| 手动/平台即时录像、即时抓图 | 不定义 | 不定义 | 定义 |

- `record_type` 门控矩阵：

| `record_type` | 本地定时 | 本地事件 | 云定时 | 云事件 |
| --- | --- | --- | --- | --- |
| `0` 关闭/未订阅 | — | — | — | — |
| `1` 事件 | — | 生效 | — | 生效 |
| `2` 全天/计划 | 生效 | — | 生效 | — |
| `3` 事件+计划 | 生效 | 生效 | 云不定义 `3` | 云不定义 `3` |

- 云侧额外条件：`storage_days > 0`；`storage_days=0` 时云策略一律不生效。
- 本地 `record_type=0` 时 `RecordManualService` / `RecordPlatformService` 也只更新状态、不落盘。
- 门控通过但没有启用的定时策略时，按 24 小时连续录像/云存处理。
- 优先级：手动/平台 > 事件策略 > 定时策略；同类型 `policy_priority` 数值小者优先，同优先级按 `policy_id` 的数值升序；非数字编号按列表顺序。
- 叠加：同一路流同一时刻只保留一份写句柄/上传任务，录像模式按位叠加；本地与云分别评估，可同时触发。
- 事件时长裁决：

```
策略 record_duration > 0  → 使用策略时长（从事件触发起算）
否则 event_record_sec > 0 → 使用属性默认时长
否则                     → 持续到事件结束；post_record_sec 仅在此时叠加
```

- 策略执行架构：四类策略的模板解析/校验、命名配置集、定时与事件条件判定统一由公共策略模块 `src/common/policy/hm_policy.c` 承担；录像模块只持久化四类配置，并向公共模块注册 `RecordService` 执行回调。录像触发层按公共 Store 的当前并集重算启停，旧 v5 扁平缓存继续兼容读取。

#### 1.11.11 设备侧实现与字段差异

- v5 变更：本地抓图拆出 `LocalPictureProperty`；`RecordSnapshotService` 增加格式/张数/间隔；`CloudPictureProperty` 增加 `picture_format`。
- 配置 `.record_policy` 版本为 `5`，顶层为 `local` / `local_picture` / `cloud` / `picture` + 四类策略 + `streams`；只接受 v5，v4 及更早版本备份为 `.bak` 后按默认值运行。
- 持久化：属性/策略变更 1s 防抖后临时文件 + rename 原子回写，单文件上限 32KB。
- 全量同步分治：本地录像、本地抓图、云录像、云图片、四类策略各自重置；未下发的能力项保留缓存；策略 `policy_list` 空列表表示清空该类。
- 严格校验：类型/范围、`record_stream_count` 与列表长度一致、码流二元组不重复、策略不超过 8 条、起止时间不等；失败整包拒绝、零变更。

> 本地与云四类策略均已按平台策略定义模板对齐，字段结构一致；设备为兼容旧 v5 缓存仍接受整数 `policy_id`、扁平 `policy_schedule` / `policy_services` 与 `event_type_mask`，但新下发与持久化统一写模板结构。

| 项 | 设备实现（本地/云一致） |
| --- | --- |
| `policy_id` | 字符串，能力项内唯一；旧缓存整数编号自动转字符串 |
| `policy_type` | `"schedule"` / `"event"` 字符串；旧缓存整数 `1/2` 兼容 |
| 定时时间段 | `policy_schedule.schedule_list[]`，单条策略最多 8 段，字段 `schedule_starttime` / `schedule_endtime` |
| 动作 | `policy_services[]` 数组，元素为 `service_id` + `service_param` |
| 事件条件 | `policy_condition.logic` + `events[]`（`event_id`），单策略最多 4 个事件 |
| 录像格式/间隔 | 策略动作不携带 `record_data_format` / `record_data_interval`；由设备按码流能力执行，`record_interval` 保留 |
| `record_type=0` 手动/平台录像 | 受门控，不落盘（服务只更新状态） |
| `record_stream_count` 与列表不一致 | 拒绝整包、零变更 |
| `policy_count` 与列表不一致 | 拒绝整包、零变更 |
| 本地录像/抓图配置 | 拆为 `LocalRecordProperty` / `LocalPictureProperty`，分别下发与回读 |
| 云图片格式 | `CloudPictureProperty.picture_format` 支持 `jpeg` / `private` |
| 多张抓图 | `RecordSnapshotService` 增加 `picture_count` / `picture_interval` |

## 2. 事件物模型定义 Event Design
- 事件统一由平台定义属性和事件ID。
- 定义平台统一的事件类型码（`event_type_id`），供第 1 章各事件能力项（如 `PTZStateEvent`、`OTAUpgradeEvent`、`RecordEvent`）上报时引用；事件按「事件ID（Event）」分组，同一事件ID下用 `event_type_id` 区分具体事件。
- 上报统一结构（`HM_TSLEventReport`，参数为 JSON 值）：
 {
    "event_type_id":0, //事件类型ID，平台统一定义，取值见 2.1～2.13 码表
 }
