# 平台物模型定义
- 全面实行平台定义设备、平台定义应用和平台定义业务，解决不同厂商之间设备兼容性问题，设备在不同APP之间兼容性问题，解决业务一致性问题。
- 同时通过物模型自定义项，实现不同厂商设备差异性问题，不同应用开发者业务差异性问题。
- 实现一套既有规则，又开放包容的物模型定义方案。

## 0. 概念设计 Name Design
- 定义规范的命名，保障各方对物模型理解一致。
 - 产品类目： --iottype--平台定义的产品类目，包括：WIFI摄像机、 4G摄像机、 低功耗摄像机、 NVR、 WIFI视频门锁、 定位器等；是平台基于物联网产品系列定义的常用产品类目，产品类目默认设置了一些产品模块配置项，方便客户创建产品时默认带入，产品类目是产品模块的预设配置集合，为方便创建产品的产物。客户可以自定义类目。

 - 能力模块： --module-- 平台根据业务集合定义能力模块，能力模块定义了能力的组合设置和默认配置，例如：图像采集模块、声音采集模块、声音播放模块、图像显示模块、网络模块、工作模式模块等；能力模块是一个业务的集合，是一个业务的预设配置项，为方便创建产品默认带入。客户可以自定义能力模块。

 - 能力项：--identify-- 能力项是具体表达某项业务能力的配置项，例如：某个镜头的编码参数配置，GPS信号参数配置、时间参数配置等；能力项是能力的最小配置组合，能力项里面项拆解出来不能单独完整表达信息。有的能力项就只有一个配置项，有的能力项有多个配置项。客户可以自定义能力项。能力项分为：属性能力项（描述一个完整的业务属性）、业务能力项（描述一个完整的业务的action）、事件能力项（描述一个完整的事件）；
 -- 属性能力项. XXXProperty，定义一个完整的模块属性，通过一堆的keyvalue，完整的表达一个事物。
 -- 业务能力项. XXXService， 定义一个功能业务操作，通过一堆的keyvalue，完整的表达一个操作。
 -- 事件能力项. XXXEvent，定义一个事件，包括事件中携带的属性参数。

 - 参数项：--key--, --value-- 参数项是最小配置单位，是针对一个参数的配置项，包括参数名称、参数类型、参数说明、参数取值范围、参数默认取值、参数取值单位等；参数项是物模型的最小配置单元，客户可以自定义参数项。标准物模型都是由参数项组成。

 - 策略：--policy--, XXPolicy 策略是一个业务组合，包括条件和动作，条件是业务触发的前提，条件可以是属性能力项和事件能力项的组合。动作是业务条件达成时要执行的动作，动作可以是业务能力项的操作，也可以是属性能力项的设置。策略是物模型定义中的业务场景，客户可以自定义策略。平台只提供策略定义模板，策略只允许选择能力项，设定能力项的判断条件和业务能力项的操作执行参数。

#### 1.14.1 设备算法能力定义能力项 -- 能力项ID："AlgorithmProperty"
- 定义算法能力定义能力项，仅定义算法模式和应用参数，不定义算法能力本身参数；
 {
    "algorithm_count":9, //支持的算法能力数量
    "algorithm_running_count":4, //支持同时工作的算法数；
    "algorithm_enabled_count":2, //当前启用的算法数；
    "algorithm_list":[
        {
            "algorithm_id":"", //算法ID,平台定义，唯一；
            "algorithm_name":"", //算法名称
            "algorithm_enable":0,//算法是否可用：0.不可用/1.可用；
            "algorithm_running":0, //算法是否运行中：0.未运行/1.运行中；
            "algorithm_sensitive": 30, //算法敏感度，0～100，数值越大，敏感度越高
            "analysis_interval":1000,//分析间隔,单位毫秒；
            "algorithm_type":0, //算法类型：0.基础算法；1.本地算法；2.云端算法；
        }
    ]
 }

 {

 {
